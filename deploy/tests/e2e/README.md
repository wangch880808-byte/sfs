# 本机 HTTP 端到端验收（e2e）

> 面向：跑 e2e 验收、或给 e2e 增加场景的开发同学和 AI 智能体。
> 适用版本：V1.0.1.10（基线 21）。
> 最后核对日期：2026-10-14。

> **同一台机器上已经有一套 `local-env.sh` 环境在跑（别的工作区、或负责人正在测试）时，不要直接 `up`、`down`**：这两个命令会删除同名容器。先按 [环境搭建](../../../docs/03-开发/环境搭建.md) 3.2 节“同一台机器上再起一套环境”，把状态目录、容器名、端口和 jar 一起换掉。

本目录有 4 套脚本：`e2e_v1015.py`、`e2e_v1017.py`、`e2e_v1018.py`、`e2e_v10110.py`，以及本机一次性环境脚本 `local-env.sh`。什么时候必须跑，见 [测试指南](../../../docs/03-开发/测试指南.md)。

**只能对本机一次性环境跑。** 后端地址必须是 `http://127.0.0.1:<端口>` 或 `http://localhost:<端口>`，不能带路径、参数或末尾斜杠，脚本会拒绝其他地址。脚本会建院系、班级、教师、学生、课程、班课、任务，还会切换当前学期，绝不能指向日常使用的库或任何服务器。

## 环境准备

用 `local-env.sh` 建一次性环境。数据库导入当前基线（`NUS-doc/3-数据库文件/ry261-test.sql`，基线 21），再经 Flyway 升到最新迁移。后端以 `prod` 配置运行，关闭验证码和接口加密，并用一次性引导功能设置管理员口令。

```sh
# 先打好后端 jar（约 3 分钟；只装了 mvnd 的把 mvn 换成 mvnd，参数相同）：
#   cd NUS-backend && mvn -q -DskipTests package -pl nus-server -am
deploy/tests/e2e/local-env.sh up
deploy/tests/e2e/local-env.sh bootstrap
deploy/tests/e2e/local-env.sh backend          # 后端在 127.0.0.1:48280
```

实测耗时：`up` 约 2 分钟，`bootstrap` 约 2–2.5 分钟，`backend` 约 0.5–1 分钟。

- 旧版本的 `FROM_BASELINE=<N>` 写法已不支持。需要从旧基线开始时，用 `BASELINE_FILE=/path/to/旧基线.sql`，版本从文件头的 `-- Flyway baseline version: N` 读取。
- 口令由脚本随机生成，保存在状态目录 `~/.cache/nus-e2e`（可用 `NUS_E2E_STATE` 改；`admin.pw`、`db.pw`、`redis.pw` 等），不打印、不进仓库。后端在状态目录里启动，上传文件也落在那里，不会往仓库里写 `.upload`。
- 脚本只停本套环境自己启动的后端（记录在状态目录的 `backend.pid`），不按端口杀进程。端口 48280 被别的程序占用时，`bootstrap`、`backend` 会直接报错退出，用 `NUS_E2E_APP_PORT`、`NUS_E2E_MGMT_PORT` 换端口，同时把下面的 `NUS_E2E_BASE_URL` 改成对应端口。
- `bootstrap` 最长等 300 秒（`NUS_E2E_BOOTSTRAP_TIMEOUT`），`backend` 最长等 300 秒（`NUS_E2E_BACKEND_TIMEOUT`）。`bootstrap` 超时的处理见环境搭建的常见问题。
- `status` 只列本套环境的容器和后端。
- 环境细节见 [环境搭建](../../../docs/03-开发/环境搭建.md)。

## 运行

4 套脚本的环境变量、输出格式相同，只依赖 Python 3 标准库：

```sh
export NUS_E2E_BASE_URL=http://127.0.0.1:48280
export NUS_E2E_ADMIN_USERNAME=admin
export NUS_E2E_ADMIN_PASSWORD_FILE=$HOME/.cache/nus-e2e/admin.pw

python3 deploy/tests/e2e/e2e_v1018.py
python3 deploy/tests/e2e/e2e_v10110.py
python3 deploy/tests/e2e/e2e_v1017.py
python3 deploy/tests/e2e/e2e_v1015.py
```

**建议按上面的顺序跑。** e2e_v1018 的“看板待审批”要求库里还没有待审批的公共课，所以放在最前面。同一个库重复跑这个场景会因为前提不满足而失败，重来就 `down` 再 `up`。

| 参数 | v1015 | v1017 | v1018 | v10110 |
| --- | --- | --- | --- | --- |
| `--dry-run`：只列场景和接口路径，不需要环境变量，也不发请求 | 有 | 有 | 有 | 有 |
| `--only <场景名>`：场景名用 `--help` 查看 | 只能一个 | 可重复 | 可重复 | 无（场景按顺序共用数据） |
| `--debug`：打印调用栈，口令会遮蔽 | 无 | 有 | 有 | 有 |
| `--keep-data`：结束时不封存本次新建的班级和公共课 | 无 | 有 | 有 | 有 |
| `--queue-size`：批改队列的提交份数，默认 201 | 无 | 有 | 无 | 无 |

- **输出**：每个场景输出 `PASS/FAIL 场景名：说明`，最后汇总；有失败时退出码非零。
- **安全**：
  - 请求发往 `/admin-api`，使用 `Authorization: Bearer <token>`、JSON `{code,data,msg}` 和独立的幂等键；
  - 禁用代理和 HTTP 跳转；
  - 不连外网、不请求钉钉、不调真实 AI；
  - 不打印、不写入任何口令，新建账号的口令由 `secrets` 在内存中生成。
- **数据**：测试数据名称带随机后缀，可以重复运行。运行失败留下的数据随一次性容器一起销毁。
- **结束时**：v1017、v1018、v10110 会把本次新建的班级与公共课**封存**。输出里显示为“已归档”，这是旧说法。这样做是为了以后每次切换学期时，不用再给它们同步、补发通知。

### 在已有的库上手工执行了迁移之后

新 `up` 的环境不用做这一步。如果在一个已经跑过后端的库上直接执行了新迁移（没有经过离线升级脚本），Redis 里的权限缓存是旧的。跑脚本、重新登录前端之前，先清掉下面 5 个前缀：`permission_menu_ids`、`menu_role_ids`、`user_role_ids`、`role`、`notify_template`。

- 前缀取自后端 `nus-module-system/.../dal/redis/RedisKeyConstants.java`，与 `deploy/offline/lib/common.sh` 的 `clear_permission_caches` 一致。
- 不要用 `FLUSHDB`，只清这几个前缀。
- 口令不要写进命令参数，不要开 `set -x`，也不要贴进报告。

`local-env.sh` 的 Redis 默认在容器 `nus-e2e-redis` 里（换过 `NUS_E2E_REDIS_NAME`、`NUS_E2E_STATE` 的，下面命令里的容器名和口令文件路径也要换），有口令。命令如下（待负责人实测）：

```sh
REDISCLI_AUTH="$(cat ~/.cache/nus-e2e/redis.pw)" docker exec -i -e REDISCLI_AUTH nus-e2e-redis sh -c '
for prefix in permission_menu_ids menu_role_ids user_role_ids role notify_template; do
  redis-cli -n 0 --scan --pattern "$prefix:*" | while IFS= read -r key; do redis-cli -n 0 DEL "$key" >/dev/null; done
done'
```

学校自定义的权限标识里如果有换行，改用 `common.sh` 的二进制安全清理函数。

## V1.0.1.10：`e2e_v10110.py`

验收公共课的认领。所有场景共用一门已上线的公共课和 4 个自动关联的班级，参与者是负责人、两位普通教师（下表的 t1、t2）、一位课程团队成员和管理员。

- 场景**按顺序执行**，前一个失败时，后面的结果只供参考。
- 不支持 `--only`。

| 场景 | 主要接口 | 主要断言 |
| --- | --- | --- |
| 认领与选项 | `claim-options`、`claim` | - 4 个班都可认领；<br>- 认领后自己看到“已认领”，别人看到“他人认领”和认领人；<br>- 选项按可认领、已认领、他人认领排序；<br>- 含已被认领班级的整批认领整体失败，不部分生效；<br>- 两位教师并发认领同一班级，只有一人成功。 |
| 只看自己的班级 | `course-manage/detail`、`list-by-course`、`class-detail` | - 普通教师只看到并能操作自己认领的班级，`list-by-course` 同样收窄；<br>- 负责人只读查看全部班级和认领人，不能操作别人的班级；<br>- 团队成员没认领时看不到班级；管理员能看到全部；<br>- 教师查看别人班级的详情被拒；负责人查看时是只读，授课教师显示为认领人。 |
| 布置任务 | `homework/create`、`copy/targets` | - 只能给自己认领的班级布置任务；负责人没认领也不能布置；<br>- 教师只看到自己布置的任务，负责人看到全部并能查看详情；<br>- 复制目标里没有别人认领的班级。 |
