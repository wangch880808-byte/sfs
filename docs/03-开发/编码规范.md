> 面向：改后端、前端代码的开发同学和 AI 智能体。
> 适用版本：V1.0.1.10。
> 最后核对日期：2026-10-14。

**规则以 AGENTS.md 为准**：

- 根目录 [AGENTS.md](../../AGENTS.md)：不可违反的规则、完成标准、必须先问人的操作；
- [NUS-backend/AGENTS.md](../../NUS-backend/AGENTS.md)：逻辑删除、数据权限、公共课权限、状态口径、错误码、缓存、性能；

本页不重复上面的内容，只补充 AGENTS.md 没写的：目录与命名、接口与 VO 的写法、错误码号段、前端组件和 API 的组织方式、提交前自查。两边说法不一致时，以 AGENTS.md 为准，并修正本页。

## 1. 后端

### 1.1 包结构与命名

包名前缀是 `cn.nus.zknu`。每个业务模块的结构相同，以 `nus-module-edu` 为例：

```
cn/nus/zknu/module/edu/
├── controller/admin/<业务>/          Controller，接口路径 /edu/<业务>/…
│   └── vo/                           请求、响应 VO
├── service/<业务>/                   Service 接口 + Impl
├── dal/dataobject/<业务>/            DO（对应一张表）
├── dal/mysql/<业务>/                 Mapper（MyBatis-Plus）
├── dal/redis/                        Redis key 常量与 DAO
├── enums/                            ErrorCodeConstants、状态枚举
├── job/                              定时任务
└── framework/                        本模块的配置
src/main/resources/mapper/<业务>/     手写 XML SQL
```

| 类型 | 命名 | 例子 |
| --- | --- | --- |
| Controller | `Edu<业务>Controller`；学生端 `AppStudent<业务>Controller` | `EduClassCourseController`、`AppStudentHomeworkController` |
| Service | `Edu<业务>Service` / `Edu<业务>ServiceImpl` | `EduHomeworkService` |
| DO | `Edu<业务>DO` | `EduClassCourseDO` |
| Mapper | `Edu<业务>Mapper`，继承 `BaseMapperX` | `EduClassCourseMapper` |
| 请求 VO | `…ReqVO`；分页 `…PageReqVO extends PageParam`；新建和修改共用 `…SaveReqVO` | `EduHomeworkPageReqVO`、`EduHomeworkSaveReqVO` |
| 响应 VO | `…RespVO` | `EduHomeworkRemoveImpactRespVO` |
| 测试 | `<被测类>Test`；H2 上测 SQL 用 `…SqlTest`；db-it 用 `…DbTest` | `EduClassDataPermissionSqlTest` |

`capacity` 模块用 `Capacity` 前缀（如 `CapacityCourseController`）；`system`、`infra`、`ai` 多数沿用脚手架原名，没有统一前缀（如 `UserController`、`ConfigController`）。新类沿用同模块、同目录已有的命名。

### 1.2 接口写法

参考 `EduHomeworkController`、`EduClassCourseController`。

- **路径与方法**：

  | 操作 | 写法 |
  | --- | --- |
  | 新建 | `POST /create` |
  | 修改 | `PUT /update` |
  | 查单个 | `GET /get?id=` |
  | 分页 | `GET /page` |
  | 列表 | `GET /list…` |
  | 恢复 | `PUT /restore` |

  其他动作用短横线动词，例如 `POST /claim`、`PUT /release`、`GET /remove-impact`。
- **“删除”接口的历史命名**：任务、班级、课程的 `DELETE /delete` 实际是**封存**（只读、仍计入分析统计），班课的封存是 `DELETE /edu/class-course/unbind`。这些都沿用了旧路径。真正删除目前只有任务有：V1.0.1.10 新增的 `DELETE /edu/homework/remove`、`/remove-list`，删除前先用 `GET /remove-impact` 给用户看影响范围。新接口按真实语义命名，界面文字按术语表写。
- **每个接口都要有**：
  - `@Operation(summary = "中文说明")`；
  - `@PreAuthorize("@ss.hasPermission('模块:业务:动作')")`；
  - 学生端接口再加 `@ss.hasRole('student')`。
  确实不需要权限的接口，要在 `EndpointPermissionsSnapshotTest` 里逐项写理由。
- **会产生数据的接口**加 `@Idempotent`，用 `RequestHeaderIdempotentKeyResolver`，`message` 写中文提示。前端请求会自动带 `X-Idempotency-Key`（见 `src/api/request.ts`）。
- **返回值**统一 `CommonResult<T>`，用 `success(...)` 包装；分页返回 `PageResult<RespVO>`。
- **参数校验**：
  - Controller 加 `@Validated`；
  - 请求体用 `@Valid @RequestBody`；
  - VO 字段用 `@NotNull`、`@Positive`、`@NotEmpty`、`@Size`；
  - 批量参数限制条数，例如 `@Size(max = 100)`。
- **组装响应时不要逐行查询**。名称、负责人等用 `convertSet` 收集编号，各一次批量查询再填进 VO，参考 `EduClassCourseController.toRespVOList`。
- **Controller 只做转换和权限**，业务规则写在 Service。公共课的权限判断统一走 `EduDataScopeService`。

### 1.3 VO 写法

- 类上加 `@Schema(description = "管理后台 - xxx Request VO")` 和 `@Data`。
- DO 和 VO 之间用 `BeanUtils.toBean` 转换。不要把 DO 直接返回给前端。
- 前端要的派生字段（`canOperate`、`canGrade`、`readOnly` 之类）由后端算好放进 RespVO，前端不要自己推断权限。
- 新增字段对旧前端要兼容：只加不改名。前端类型里加注释说明“旧版后端没有”时怎么处理，参考 `api/edu/homework/index.ts` 的 `canGrade`。

### 1.4 错误码号段

格式是 `1_<模块 3 位>_<业务 3 位>_<序号 3 位>`，写在各模块的 `enums/ErrorCodeConstants.java` 里，按业务分节注释。

| 模块 | 号段 | 已用到（2026-10-14） |
| --- | --- | --- |
| infra | `1_001_xxx_xxx` | `1_001_006_xxx` |
| system | `1_002_xxx_xxx` | `1_002_029_xxx` |
| ai | `1_040_xxx_xxx` | `1_040_012_xxx` |
| edu | `1_050_xxx_xxx` | `1_050_018_xxx` |
| capacity | `1_060_xxx_xxx` | `1_060_001_xxx` |

- 先在对应业务的分节里接着往下编号。新业务就开一个新的中间三位，并加一行分节注释。
- edu 的重号由 `ErrorCodeConstantsUniqueTest` 检查，其他模块没有这个测试，新增时自己全文搜索一遍。
- 前端或 e2e 需要按错误码判断时，直接用数字。例如 e2e 里的 `1050005002` 表示“已提交”。改错误码等于改接口约定。

### 1.5 SQL

- 简单条件用 `LambdaQueryWrapperX`。复杂查询写 XML，放在 `resources/mapper/<业务>/`。
- 手写 SQL 的 `deleted = 0`、数据权限测试见 [NUS-backend/AGENTS.md](../../NUS-backend/AGENTS.md)。
- 公共课同步、认领相关的条件，复用 `EduClassCourseMapper` 里的常量（例如 `IDLE_AUTO_LINK_CONDITION`），不要另写一份。

## 2. 前端

### 2.1 目录

都在 `NUS-front/apps/web-antd/src/` 下，详见 [NUS-front/README.md](../../NUS-front/README.md)。

| 目录 | 放什么 |
| --- | --- |
| `views/<模块>/<业务>/` | 页面。`index.vue` 是列表页；`data.ts` 放表单 schema、表格列；`modules/` 放弹窗、抽屉；纯逻辑写成同目录的 `xxx.ts` 和 `xxx.test.ts` |
| `api/<后端模块>/<业务>/index.ts` | 接口函数和类型，目录与后端模块对应：`edu`、`capacity`、`system`、`infra`、`ai` |
| `components/` | 跨页面复用的组件，每个一个目录，带 `index.ts` 导出 |
| `adapter/` | vben 的表单（`form.ts`）、表格（`vxe-table.ts`）、组件适配。翻页回退等统一行为写在这里 |
| `utils/` | 无界面的工具。状态文字和颜色映射集中在 `utils/status*.ts` |
| `styles/theme/` | 颜色 token（`palette.ts`）和非颜色 token（`tokens.css`） |

### 2.2 命名

- 文件和目录用小写短横线：`class-relations.ts`、`remove-confirm.ts`、`student-manage-modal.vue`。
- 少数历史组件用大驼峰，例如 `HomeworkForm.vue`，改动时不用顺手改名。
- 测试和被测文件放一起，名字相同，加 `.test.ts`。
- 接口函数用动词开头，和后端动作对应：
  - `getXxx`、`getXxxPage`、`getXxxList`；
  - `createXxx`、`updateXxx`；
  - `deleteXxx`（对应后端 `/delete`，即封存）；
  - `removeXxx`（真正删除）；
  - `restoreXxx`。

### 2.3 API 写法

参考 `api/edu/homework/index.ts`：

```ts
export namespace EduHomeworkApi {
  /** 实训任务信息 */
  export interface Homework { id?: number; homeworkName: string; /* … */ }
  export interface HomeworkPageReqVO extends PageParam { /* … */ }
}

/** 新建实训任务 */
export function createHomework(data: EduHomeworkApi.Homework) {
  return requestClient.post('/edu/homework/create', data);
}
```

- 类型放在与文件同名的 `namespace` 里，字段名和后端 VO 一致，每个字段写中文注释。
- 统一用 `#/api/request` 的 `requestClient`。不要在页面里直接用 axios 或 fetch。
- 耗时长的接口（AI、导入导出）用 `LONG_REQUEST_TIMEOUT`。
- 页面只调用 API 函数，不在页面里拼接口路径。

### 2.4 组件与页面

- 列表页用 `useVbenVxeGrid`，弹窗用 `useVbenModal`，表单用 vben 表单 schema（写在 `data.ts`）。
- 按钮权限写 `auth: ['edu:class:create']`，和后端 `@PreAuthorize` 的权限码一致。
- 状态显示用 `StatusTag`，空状态用 `EmptyState`，用户填写的 HTML 用 `RichHtml`。
- 能写成纯函数的逻辑（选项构造、校验、权限判断、文案拼接）抽到 `.ts`，并写 vitest 测试。`.vue` 文件只负责界面。

## 3. 提交前自查

先跑 `scripts/check-all.sh`，再逐项核对：

- [ ] 改动只解决一个问题，分支名、提交信息符合 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
- [ ] 后端新接口：
  - 有 `@Operation`、`@PreAuthorize`；
  - 会产生数据的加了 `@Idempotent`；
  - 更新了 `endpoint-permissions.tsv`，跑了权限矩阵。
- [ ] 新 SQL：每张表都有 `deleted` 条件；涉及 `edu_class`、`system_users`、`system_dept` 的有 H2 拦截器测试；复杂 SQL 跑了 db-it。
- [ ] 新错误码在正确号段内、不重号，提示语是中文、告诉用户怎么办。
- [ ] 前端：
  - 权限码和后端一致；
  - 文字过了 `tests/copy` 扫描，符合 [术语表](../01-产品/术语表.md)；
  - 颜色只用 `--nus-*` 变量，深色和浅色都看过。
- [ ] 表单的级联、校验时机、编辑回显在浏览器里实测过。
- [ ] 改了表结构，按 [数据库迁移](数据库迁移.md) 走完迁移、基线、check 三件套。
- [ ] 修 bug 有能复现的测试；新逻辑有测试。
- [ ] 没有口令、密钥、真实学生数据；`gitleaks dir .` 无告警。
- [ ] 用户能看到的变化写进 `CHANGELOG.md` 的“未发布”；操作方式变了，更新用户操作手册。
- [ ] 更新 `docs/06-交接/当前状态.md`。
