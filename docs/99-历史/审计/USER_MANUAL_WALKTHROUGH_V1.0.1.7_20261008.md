# V1.0.1.7 用户手册编写走查记录（2026-10-08）

编写《用户操作手册》时，按管理员、学校教务管理员、教师、学生四种身份把主要页面完整走了一遍。本文件记录这次走查的环境、做过的操作和发现的问题。手册见 [user-manual/用户操作手册.md](user-manual/用户操作手册.md)。

## 1. 环境

| 环境 | 版本 | 用途 |
| --- | --- | --- |
| PVE 107（<测试服务器>） | V1.0.1.7（前后端镜像 `V1.0.1.7`，Flyway 18） | 管理员端页面与弹窗截图；用已登录的 admin 会话通过界面新建数据 |
| 本机一次性环境 | V1.0.1.7 当前 release 分支（基线 16 → Flyway 18，前端开发服务器） | 教师、学生、学校教务管理员页面；演示数据由脚本生成 |

说明：

- 107 上只有 admin 一个账号，没有教师和学生账号。本次没有在 107 上新建教师或学生账号，也没有用这类账号登录，所以教师端和学生端的流程都在本机环境上验证。
- 本机环境的演示数据包括：1 个班级、12 名学生、1 名教师、1 名学校教务管理员、3 门课程（其中 1 门在等待公共课审批）、6 个实训任务。提交覆盖已批改、待批改、已打回三种状态，另有师生留言。
- 本次没有验证：AI 初评与 AI 研判（没有接入模型）、文件上传与下载、Excel 导入、微信小程序。

## 3. 发现的问题

严重程度：**中**表示会误导使用或导致流程走不通；**低**表示文案、显示类问题；**待确认**表示需要人工复核或产品判断。

| # | 严重程度 | 位置 | 现象 | 复现环境 |
| --- | --- | --- | --- | --- |
| 1 | 中 | 能力培养 → 教学过程分析 | 课程没有任何已批改任务（已分析任务为 0）时，「过程结论」仍写着“当前课程整体通过率为 100%，达标情况稳定”。 | 107 |
| 2 | 中 | 能力培养 → 教学问题研判 | 没有选择班级、也没有成绩时，页面显示综合研判得分 71.6、风险等级「中风险」，雷达图和问题热度也有数值，看上去像真实结论。 | 107 |
| 3 | 中 | 课程详情（管理员视角） | 同一门课程，教师看到「实训任务 4」，管理员看到「实训任务 0」。卡片说明写的是“课程下已发布的任务总数”，与实际统计口径（看起来按创建人过滤）不符。 | 本机 |
| 4 | 中 | 课程详情（教师视角） | 教师的课程详情没有「添加班级」按钮（教师角色没有绑定班课的权限），只能请管理员添加；但空状态提示写着“把班级添加到本课程后，才能给班级发布实训任务”。需要确认：是按设计只允许管理员绑定，还是漏配了权限。 | 本机 |
| 5 | 中 | 学生 → 能力分析 / 实训报告 | 任务没有挂一级指标时，批改后「能力分析」仍显示“待评定”，「实训报告」却显示已评定 1、达标率 100%，两页口径不一致。新建任务时一级、二级指标不是必填项，教师很容易漏选。 | 本机 |
| 6 | 中 | 角色配置 | 预置角色「学院教务管理员」没有分配任何菜单，用这个角色登录后什么都看不到。 | 本机基线库（107 未核实） |

| 8 | 低 | 教务组织 → 学期管理 → 学期收尾 | 弹窗打开后切换路由（例如浏览器前进/后退），弹窗不会关闭，会盖在新页面上。 | 107 |

| 17 | 待确认 | 个人中心（admin） | 「用户手机」「用户邮箱」标为必填，内置管理员没有手机和邮箱时，无法只修改姓名。 | 107 |

## 4. 与权限相关的观察（非缺陷）

- 学校教务管理员是只读角色：可以看组织架构、班级、教师、学生列表，审批公共课，查看管理员看板。班级、教师、学生列表里没有任何操作按钮。建班、建账号、设置学期都由平台管理员完成，手册按这个分工编写。
- 教师侧边栏是重新组合过的：工作台、教学（实训课程管理、课程资源、题库管理）、实训任务管理、评价指标管理、留言互动。它和后端菜单树的分组不同，手册以教师实际看到的为准。
