# P0 数据交换与报表实施基线

> **历史归档（不作为现行规范）**：本文是 2026-09-01 的 P0 实施计划，仅作历史记录保留。现行行为以代码、Flyway 迁移和 `docs/OFFLINE_DEPLOYMENT_OPERATIONS.md` 为准。

状态：已批准，允许实施  
批准日期：2026-09-01  
适用仓库：`NUS-backend`、`NUS-front`

## 1. 实施范围

本轮只实施以下 P0 能力：

1. 组织、专业与班级主数据导入导出。
2. 学生档案、学生班级关系和班级花名册导入导出。
3. 任务成绩册导出，以及“上传、预检、草稿、确认”式成绩导入。
4. 学生明细、课程、班级、院系报表 Excel/PDF 导出。
5. 学生个人训练报告服务端 PDF 导出。

教师批量导入、题库导出、指标体系导入导出、班课计划导入导出和课程归档包不在本轮范围内。

## 2. 不可变业务规则

- 所有导入必须经过“上传预检 -> 差异确认 -> 原子提交 -> 结果回执”。
- 预检存在致命错误时不允许确认；确认阶段任一写入失败则整批回滚。
- 导入更新时，空单元格不覆盖原值。
- 学生班级关系只新增或恢复，不通过导入隐式移出学生。
- 已存在的非学生账号不得作为学生关联班级。
- 成绩导入仅处理已提交或重新提交记录，先生成批改草稿，教师确认后写入正式成绩。
- 所有导出继承页面完整筛选条件，不受页面分页限制。
- 管理员使用全局数据范围；教师仅使用本人负责课程范围；学生仅使用本人数据。
- 导入导出必须记录权限范围、操作者、时间、模板版本和结果摘要。

## 3. 数据模型基线

### 3.1 主数据标识

- `system_dept` 增加 `dept_code`、`dept_type`；`dept_code` 全局唯一。
- `edu_class` 增加 `class_code`；`class_code` 全局唯一。
- `system_users.username` 增加唯一约束。
- `system_user_profile.user_id` 增加唯一约束。
- `edu_class_student` 对班级和学生建立唯一关系；重新加入时恢复旧关系。

### 3.2 报表口径

- 新增 `edu_homework_assignee`，任务发布时固化应提交学生范围。
- `edu_homework_record` 增加 `redo_count`，打回重做时原子累加。
- 现有发布任务按当前班级成员回填快照，历史值标记为迁移推定数据。

### 3.3 导入批次

- 新增 `edu_import_batch` 保存业务类型、批次号、模板版本、源文件、SHA-256、状态、计数、处理选项和操作者。
- 新增 `edu_import_batch_item` 保存工作表、行号、业务键、标准化数据、动作、校验错误及变更前后快照。
- 源文件及错误文件使用私有文件存储，业务接口校验权限后下载。

## 4. 模板基线

所有模板使用 `.xlsx`，编码和学号列强制为文本格式；包含只读“模板信息”页和隐藏“数据字典”页。

### 4.1 组织班级模板 V1

`学院专业`：组织编码*、组织名称*、组织类型*、上级组织编码*、排序、状态、负责人账号、电话、邮箱。  
`班级`：班级编码*、班级名称*、专业编码*、入学年份*、培养层次*、学制*、状态、备注。

### 4.2 学生主数据模板 V1

`学生档案`：学号*、姓名*、性别、主专业编码*、入学年份*、手机号、邮箱、状态。  
`班级关系`：学号*、班级编码*、备注。

### 4.3 班级花名册模板 V1

`班级花名册`：学号*、姓名*、性别、手机号、邮箱、跨专业或年级加入备注。  
班级由上传入口确定，不允许在表内修改。

### 4.4 成绩导入模板 V1

`成绩录入`只读列：任务编号、任务名称、班级、学号、姓名、提交状态、满分、达标线。  
可编辑列：成绩*、教师评语。  
隐藏列：记录 ID、行令牌、模板校验值。

## 5. 接口基线

统一导入流程：

```text
GET  /edu/data-exchange/templates/{bizType}
POST /edu/data-exchange/imports/{bizType}/preview
GET  /edu/data-exchange/imports/{batchNo}
POST /edu/data-exchange/imports/{batchNo}/confirm
GET  /edu/data-exchange/imports/{batchNo}/errors
POST /edu/data-exchange/imports/{batchNo}/cancel
```

业务导出：

```text
GET /edu/master-data/organization/export
GET /edu/student-data/export
GET /edu/class/student/export
GET /edu/homework-record/gradebook/export
GET /edu/report/course/export
GET /edu/report/class/export
GET /edu/report/department/export
GET /edu/report/student-detail/export
GET /edu/student/capacity/report/export-pdf
```

## 6. 前端基线

- 共用 `ImportWizard` 负责模板下载、选文件、预检、差异确认、提交和错误文件下载。
- 组织页、学生管理页、班级学生弹窗和任务批改页分别提供对应入口。
- 教育模块教师/学生页面不再复用可自由指定用户类型的系统用户导入弹窗。
- 报表导出使用格式菜单；请求参数必须由当前筛选状态完整生成。
- PDF 下载使用后端生成文件，不再使用 `window.print()` 作为正式导出。
