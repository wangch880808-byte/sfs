# 师砺平台 V1.0.1.7 增量更新说明

**适用范围**：
- 已安装 V1.0.1.6（Flyway 版本 17）的离线环境，升级后 Flyway 版本为 18。
- 从 V1.0.1.5 直接升级同样可行，升级时依次执行 V17、V18。这种情况请同时阅读 V1.0.1.6 的更新说明：界面改版、导航编排和术语统一都在那一版。

本版修复 2026-10-07 全面审查中发现的可靠性与业务流程问题，界面风格不变。主要内容有：
- AI 初评不再静默漏评；
- 批改防并发覆盖，并可以撤销；
- 等级闯关不再回锁；
- 支持个别延期与自动提醒；
- 学期切换与复制任务；
- 成绩册导入不再误改；
- 写死的角色判断改为配置；
- 升级失败可以自动回滚。

## 一、升级前必读

1. **升级脚本换了流程**，见“十一、升级步骤”。
   - 先预检，预检不通过时平台不会停；
   - 停机后才备份数据库；
   - 停机后任何一步失败都会自动回滚到原版本；
   - 新增 `nusctl rollback`。
2. **取消“AI 自动批改”**。这个选项此前实际上不生效：提交一直停在“待批改”。
   - 批改方式现在只有“仅人工批改”和“AI 初评 + 教师复核”两种；
   - 已选“AI 自动批改”的任务由 V18 改为“AI 初评 + 教师复核”。
3. **批改、打回的学生通知会晚 10～20 秒送达**。教师在撤销期内（默认 10 秒）可以撤销，撤销后学生不会收到通知。
4. **公共课审批改为按权限判断**。
   - 学校教务管理员获得“公共课审批”按钮权限，以及审批所需的“实训课程管理”页面和课程查询权限；
   - 学院教务管理员不授予，公共课面向全校，由学校层面审批；
   - 学校自建的角色如需审批，在“角色管理”里勾选“公共课审批”。
5. **新增三个定时任务**，升级后自动生效，可在“定时任务”中停用：
   - 截止前提醒（每小时）；
   - 教师新提交汇总（每 10 分钟检查一次）；
   - AI 调用日志清理（每天 03:35）。
6. **等级闯关规则调整**，见“四”。已经解锁的等级以后不会再被锁上。
7. 新增的可调参数都在“参数配置”中，见“十、新增参数”。默认值与原有行为一致，或取了稳妥的值。

## 二、批改

1. **防并发覆盖**：
   - 批改、打回、学生重交都只在记录仍处于预期状态时才写入。
   - 两位教师同时批改同一份，后保存的一方会看到“这份提交已被他人更新，请刷新后再看”，已填的分数和评语保留；比较精确到毫秒。
   - 连点两次不会产生两条评分记录，学生也不会收到两条通知。
2. **重复提交**：同一学生重复提交同一任务时，提示“该任务已提交，请勿重复提交”，不再显示“系统异常”。
3. **撤销**：保存批改或打回后，底部显示“已保存 · 撤销（倒计时）”。撤销会恢复原来的状态、分数、评语和重做期限，并记入评分轨迹。撤销时长见参数 `edu.grading.undo-seconds`。
4. **批改页**：
   - 不再限制 200 份，总数按实际提交数显示；
   - “保存并下一份”按当前筛选顺序前进；
   - 快捷键：J/K 或 ↑/↓ 切换学生，Ctrl（⌘）+ Enter 保存并看下一份；
   - 保存后只刷新当前这一份；
   - 评分和评语自动存为草稿：切换学生不会丢，列表上标“草稿未保存”；有未保存的草稿时，离开页面会先确认；
   - 分数和评语的校验提示显示在输入框下方。

## 三、AI 初评与 AI 管理

1. **可靠排队**：
   - 学生提交或重交时，AI 初评先在数据库里排队，提交成功后才开始处理；
   - 队列满或服务重启都不会丢失，重启后会自动续跑。
2. **失败看得见**：
   - 每一份没有完成的初评，都写明原因和下一步，常见原因有模型报错、超时、附件读取失败、已被重交取代；
   - 可以重试的失败会通知任务教师（同一任务 6 小时内最多一条）。
3. **批量生成 AI 初评改为只补缺**：只为没有初评、初评失败或被跳过、初评对应旧提交的记录生成，已有的初评不覆盖。单份可用“重新生成”。
4. **提示词管理**（新菜单，超级管理员）：
   - 系统提示词改存数据库，可以新建版本、启用、和默认内容对比；
   - 保存时检查结果解析所需的格式要求，缺少时拒绝保存。
5. **调用日志**（新菜单，超级管理员）：
   - 每次调用模型都记一条：业务、模型、发起人、令牌数、耗时、是否成功；
   - 另有按天、按业务的汇总；
   - 默认保留 180 天。
6. **额度与熔断**：
   - 可设置全平台每日令牌上限、每人每日调用次数上限，默认都不限；
   - 每人上限只统计用户在页面上主动发起的调用，后台初评不计入；
   - 同一模型连续失败 5 次后，60 秒内直接提示“AI 服务暂时不可用，请稍后再试”；
   - 重试只针对限流、服务端错误和超时，总时长不超过单次调用的上限。
7. **AI 出题“重新生成”改为后台执行**：弹窗等待结果，关掉再打开会接着等。

## 四、等级闯关与往期内容

1. **计入规则**：
   - 某一等级的达标率 = 达标任务数 ÷ 计入的任务数；
   - 只有已过截止时间（含个别延期）、或学生已经提交的任务才计入；
   - 打回、重交期间沿用上一次批改的成绩（已撤销的批改不算）；
   - 在等教师批改的任务单独统计，不算未达标。
2. **解锁后不再回锁**：教师新发布任务、调整及格线、管理员调高解锁比例，都不会让已解锁的等级重新锁上。
3. **插班学生**：没有被分配到上一等级任何任务的学生（加入班级时那些任务已截止），不会因此被一直锁住，见参数 `edu.unlock.late-joiner-pass`。
4. **学生能看到原因**：
   - 课程详情的“等级闯关”显示每一级的进度、要求的比例和未解锁原因，如“还差 1 个任务达标”“有 1 个任务在等教师批改”；
   - 打开未解锁的任务时，页面里写明原因，不再弹红色提示。
5. **修改等级与及格线**：
   - 任务已有提交后不能再改等级；
   - 及格线可以改，保存前提示影响，并记入操作日志（谁、何时、原值→新值）。
6. **归档后历史可见**：
   - 班级、课程或班课归档后，学生仍能查看往期任务的成绩反馈、提交记录和能力分析，任务中心新增“往期任务”；
   - 往期课程的详情页只读；
   - 已归档的班级或班课不能再打回作业、回复留言，提示写明原因和恢复办法；
   - 教师查看已归档任务的统计时为只读。

## 五、截止时间、延期与提醒

1. **个别延期**：
   - 教师在任务详情中，为没有提交的学生单独设置更晚的截止时间并写明原因，学生会收到通知；
   - 学生的任务列表和提交页显示实际截止时间，并标明“教师已为你延期”；
   - 打回重做的期限规则不变。
2. **截止前提醒**：截止前 24 小时内还没有提交的学生，会收到一次提醒，每人每个任务只提醒一次。
3. **一键催交**：
   - 任务详情中可以催交还没有提交的学生；
   - 同一任务默认 60 分钟内只能催交一次，结果显示通知了多少人。
4. **任务变更通知**：已发布的任务只有截止时间、任务内容、附件要求、提交方式、满分或及格线变化时才通知学生，并写明改了什么，改错别字不再群发。
5. **教师新提交汇总**：同一任务每小时最多通知一次“「任务名」有 N 份新提交（含 M 份重交）待批改”，点开直接进入批改页；两次检查之间的提交不会漏掉。

## 六、学期与任务复制

1. **复制任务**：
   - 在任务列表勾选任务后，可以“复制到”其他学期或其他班级；
   - 复制出来的是草稿，内容、等级、分数、批改方式、指标原样保留，截止时间清空，发布前填写；
   - 只能复制自己布置的任务。
2. **学期收尾**：
   - “学期管理”新增学期收尾向导，列出所选学期还在用的班课、进行中的任务、待批改的提交和公共课关联；
   - 勾选后批量归档，归档后可以恢复。
3. **添加班级时从已配置的学期中选择**，不再手动填写学期名。以前手填的学期名照常显示。
4. **公共课**：
   - 切换当前学期、审批或上下线公共课后，页面立即返回，公共课关联、补发任务和通知在后台执行，通常几分钟内完成；
   - 新班级加入当前学期后，会自动收到“课程已分配”通知，并补发这门公共课面向所有班级、还没截止的任务；
   - 补发中途出错时会记下“待补发”，下次同步（含每天的定时同步）自动补上；
   - 切换学期或公共课下线时，系统自动建立、没有进行中任务的旧关联会自动归档，可以恢复；
   - 可用参数关闭这两项。

## 七、成绩册与留言

1. **成绩册导入**：
   - 分数和评语都没变的行直接跳过：不写评分记录、不改 AI 初评、不通知学生；
   - 导入预检显示各类跳过原因及数量；
   - 已重交的记录导出时“成绩”留空，原成绩放在只读列“打回前成绩”，避免旧成绩被当作新提交的终评；
   - 预检之后记录有变化（如学生刚刚重交、教师改了评语）时，整批不写入，并指出是哪一行；
   - 升级前已经做过预检、还没确认的成绩册导入，升级后需要重新上传预检；
   - 以前导出的成绩册仍可导入。
2. **留言通知**：
   - 学生留言会通知课程负责教师、课程团队成员和班课助教；
   - 打开留言时，对应的通知一并标为已读，铃铛上的未读数随之更新。

## 八、学生提交与防错

1. **附件**：
   - 选择文件时就检查类型、大小和个数，提示文字写明上限，不用等上传完才报错；
   - 上传失败的附件可以单独重试，不影响其他附件；
   - 上限可配置，默认 10 个、单个 100 MB、合计 300 MB。
2. **草稿**：
   - 输入后约 2 秒自动保存，离开页面、切到后台时也会保存；
   - 草稿包括已上传的附件；
   - 再次打开时提示“已恢复上次未提交的草稿”。
3. **未保存提醒**：任务表单、课程表单、提交页等较长的表单，有改动时离开或关闭会先确认；点弹窗外的空白处不会误关。
4. **报错提示**：
   - 同一条错误几秒内只提示一次；
   - 页面里已经显示原因的，不再另弹红框；
   - 未读通知的定时刷新出错时不再弹提示，断网时会逐步拉长刷新间隔。

## 九、权限与配置

1. **角色编码改为参数配置**：`edu.role.*`，默认值与原来写死的一致。
   - 判断“谁是管理员、谁是教师、谁是学生”的地方都改为读取这些参数；
   - 学生、教师的编码不建议修改。
2. **多重角色的界面形态**：优先级为管理员 > 教师 > 学生，只有纯学生账号使用顶部导航。
3. **课程团队与班课助教改存关联表**：以前以逗号分隔的 ID 串存放，不同页面的匹配方式不一致，带空格或全角逗号时会出现“这里看得到、那里看不到”。现在统一读取关联表 `capacity_course_member`、`edu_class_course_assistant`，升级时由 V18 从旧 ID 串回填。旧 ID 串本版仍同步写入，供回退使用，计划在下一版本停止写入。
4. **内部结构**：教学模块改为通过课程、AI 模块的公开接口取数，不再直接读写其内部表，并有自动检查守护；状态值统一用常量。对使用者没有可见变化。

- **其他**：上面列出的参数和三个定时任务。

## 十二、升级步骤

1. 把升级包复制到服务器，执行 `sha256sum -c` 校验压缩包。
2. 解压后在包目录执行（建议在 `tmux` 或 `screen` 中）：`sudo ./upgrade.sh "$PWD"`。
   - **预检**（不停平台）：文件校验、目标版本是否已安装、镜像标签、MySQL 和 Redis 健康、磁盘空间（至少“数据库大小 × 2 + 新镜像大小”，不低于 2 GiB）、Flyway 能否在线上库通过校验。
   - **准备**（不停平台）：构建新镜像，启动并检查监控服务。
   - **切换**：备份 `.env` → 停止前端和后端 → 备份数据库 → 换上新配置 → 执行 V18 → 清理菜单、权限与通知模板缓存。
   - **启动**：健康检查通过后，才把 `/srv/nus/current` 指向新版本。
   - 日志在 `/srv/nus/logs/upgrade/`，每次升级在 `/srv/nus/upgrades/` 留一份记录（不含密码）。
   - 脚本向 MySQL、Flyway 传递口令一律通过环境变量，不出现在命令行参数里（宿主机 `ps` 看不到）。
3. 看屏幕最后一段：

   | 屏幕最后一段 | 含义 | 怎么办 |
   |---|---|---|
   | `Upgrade to V1.0.1.7 completed` | 升级成功 | 按第 4 步检查 |
   | `Nothing was stopped` | 预检或准备没通过，平台没有停 | 按提示处理原因（如清理磁盘）后重新执行 |
   | `UPGRADE FAILED - V1.0.1.x IS RUNNING AGAIN` | 停机后失败，已自动回滚，原版本在运行，数据库恢复到停机时的状态 | 把升级日志发给开发方，原因在日志里 FAILED 一行之前 |
   | `AUTOMATIC ROLLBACK DID NOT FINISH`（退出码 3） | 自动回滚也失败，平台处于停止状态 | 按屏幕列出的命令依次执行（每条可重复执行），然后执行 `sudo nusctl status` |

4. 升级后执行 `nusctl status`、`nusctl doctor`，并用教师、学生、管理员账号登录检查常用页面。

## 十三、回滚

升级失败会自动回滚，通常不用手动操作。升级成功后如需退回上一版本（107 退回 V1.0.1.6，学校服务器退回 V1.0.1.5）：

1. **执行**：

   ```bash
   sudo nusctl rollback previous
   ```

   命令先列出要用的数据库备份（升级时停机后做的那份）、`.env` 备份和原版本镜像。输入 `yes` 后依次：
   1. 停止前端和后端，把当前数据库另存为安全备份（路径会打印出来）；
   2. 删除并重建数据库，导入升级时的备份；
   3. 恢复升级前的 `.env`；
   4. 清理缓存；
   5. 用原版本启动并做健康检查；
   6. 把 `/srv/nus/current` 指回原版本。
2. **注意数据**：**升级之后产生的数据（提交、批改、留言、通知等）会丢失**，它们只保存在第 1 步的安全备份里。数据库迁移不能单独回退。
3. **检查**：执行 `sudo nusctl status`、`sudo nusctl logs backend --since 30m --error`。
4. **中途失败**：平台保持停止，屏幕会打印一条可以重复执行的 `nusctl rollback ... --yes` 命令，修复原因后照着执行。
5. **不要**手动执行不带参数的 `docker compose up -d`：它不读取 `/srv/nus/config/.env`，也不带域名 Nginx 覆盖文件。需要手动启动时用 `sudo nusctl start`。

> V1.0.1.6 更新说明“八、回滚”中的手动步骤已不适用，以本节为准。

## 十四、升级后需要学校确认的事项

1. **公共课审批人**：默认只有超级管理员和学校教务管理员能审批。如需其他角色审批，在“角色管理”中勾选“公共课审批”。
2. **定时任务**：截止前提醒和教师汇总默认开启。不需要时，在“参数配置”中把 `edu.remind.enabled` 设为 false、`edu.notify.teacher-digest-minutes` 设为 0。
3. **AI 额度**：默认不限。需要控制费用时，设置 `ai.daily-token-quota` 和 `ai.user-daily-call-quota`，并在“调用日志”中查看用量。
4. **学校自建的教师类角色**：“复制任务”“个别延期”“催交”只授予了编码为 teacher 的角色，自建角色需要在“角色管理”中勾选。

## 十五、已知问题

1. **学生角色的数据范围仍为“全部”**（1.0.1.5 已说明），计划在后续版本处理。
2. **公共课留言通知**：班课表没有“本班任课教师”字段，公共课的留言通知发给课程负责教师、课程团队和班课助教，不能只发给本班任课教师。
3. **后续改进**：
   - 下一版本停止写入并删除旧的助教 ID 串列；
   - MySQL 容器的健康检查仍在容器内以命令行参数传递口令，为避免升级时重建 MySQL 容器，本版不改。
4. **只回退应用、不回退数据库**（不建议）时，回退期间改动的课程团队与班课助教不会进入关联表。请用 `nusctl rollback`，它会连同数据库一起恢复。
