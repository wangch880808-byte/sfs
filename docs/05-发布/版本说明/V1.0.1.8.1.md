# 师砺平台 V1.0.1.8.1 补丁更新说明

**适用范围**

- 已安装 V1.0.1.8（10 月 9 日或 10 月 10 日上午的升级包）的服务器：直接执行 `sudo ./upgrade.sh` 即可，**不需要先回滚**，数据库不变（Flyway 仍为 19，本补丁没有数据库变更）。
- 还停留在 V1.0.1.7 的服务器：也可以直接用本包升级，效果等同于完整的 V1.0.1.8。

**为什么是新版本号**：升级脚本要求每个包使用新的版本号，同一版本号不能重复安装。早期装过 V1.0.1.8 的服务器，用这个补丁版本号就能拿到后续的修复。

本包与最终版 V1.0.1.8 的代码完全相同，内容见下方“九、补充修复”，主要包括：

1. 账号邮箱、手机号没有改动时，保存不再提示“已存在”；教师、学生、用户列表显示邮箱；
2. 学生导入模板改为按班级导入（旧模板不能再用，请重新下载）；
3. 大文件导入改为后台执行并显示进度，不再“转完圈没下文”；导入提速；
4. 学生修改初始密码页：表单看不见、点按钮没反应的问题已修复，新增“返回登录”；
5. 耗时较长的操作不再提前报超时；AI 流式输出不再攒一大段才显示。

升级后请执行 `sudo nusctl status` 确认各服务健康；如需回退，执行 `sudo nusctl rollback previous`，会回到升级前的版本和数据库备份。

# 师砺平台 V1.0.1.8 增量更新说明

**适用范围**

- 已安装 V1.0.1.7（Flyway 版本 18）的离线环境，升级后 Flyway 版本为 19。
- 从更早版本升级时，会依次执行中间各版本的迁移，请同时阅读对应版本的更新说明。

本版修复 V1.0.1.7 用户手册走查中发现的问题（见 [走查记录](../../99-历史/审计/USER_MANUAL_WALKTHROUGH_V1.0.1.7_20261008.md)），并补上一处课程权限的安全漏洞。界面风格不变。

## 一、升级前必读

1. **安全修复**：
   - 绑定、解绑、恢复班级课程时，后端现在会检查当前用户是否有权管理这门课程。此前只检查菜单权限。
   - “按班级查看课程”接口也加了访问校验。
2. **教师可以给自己的课程添加班级**：
   - 课程负责人和课程团队成员（助教）都可以在“课程详情 → 班级”里点“添加班级”。
   - 其他教师即使能看到公共课，也不能给它添加班级。
3. **学院教务管理员可以维护本学院的数据**，范围按账号所属学院限定：
   - 能维护的内容：本学院的组织查询，班级的新建、修改、归档、学生管理，教师和学生账号的新建、导入、修改、停用、恢复、重置密码，以及导出本学院用户；
   - 操作其他学院的数据一律返回“无权限”；导入时，其他学院的行会在预检中跳过，原因写“不在本学院”；
   - 本版**不包含**课程、任务、统计看板，也没有公共课审批，这些仍由学校层面负责；
   - **使用前提**：学院教务管理员的账号必须挂在**学院**节点上，班级挂在其下属专业上。账号没有设置所属学院时，系统会提示“账号未设置所属学院，请联系管理员”；
   - 学院教务管理员不再被当作全局管理员。
4. **“通知公告”菜单已停用**：师生端并没有展示公告的位置，系统提醒统一走右上角铃铛的站内通知。已有的公告数据保留。
5. **升级后请重新登录**：升级脚本会自动清除权限和通知模板缓存，但浏览器里已登录的会话需要重新登录，新的菜单权限才会生效。
6. **学生导入模板改版**：按班级导入，旧版学生模板不能再用，请重新下载。详见“九、补充修复”。

## 二、统计与分析

1. **教学过程分析**：课程还没有已批改的任务时，不再出现“整体通过率 100%，达标情况稳定”这类结论，改为“还没有已批改的任务，暂不判断达标情况”，统计卡片显示“—”。
2. **教学问题研判**：没有数据时，综合研判得分和风险等级显示“暂无数据”，雷达图和热度图显示空状态，“AI 研判”按钮不可用。此前会显示 71.6 分、“中风险”。
3. **课程详情的任务数**：以下用户都能看到课程下的全部任务——管理员、有公共课审批权限的人、课程负责人、课程团队成员。此前管理员看到的是 0。
4. **学生能力分析与实训报告口径统一**：
   - 任务计数（总任务、已评定、已达标、达标率）统计全部任务；
   - 能力画像（雷达图、综合达标率、获证判断）只统计关联了能力指标的任务；
   - 有已评定但未关联指标的任务时，页面会写明“有 N 个已评定任务未关联能力指标，不计入能力画像”。
5. **能力图表**：指标少于 3 个时改为横向条形图，不再画成一条线。
6. **管理员看板“需要关注”**：直接列出待审批的公共课申请数，学校教务管理员也能看到。

## 三、教师

1. **新建实训任务**：
   - “指定课程”“指定班级”标出必填，未填写时在输入框下方提示；
   - 没有选择能力指标时会提醒“这次成绩不会计入学生的能力分析”，但不阻止保存；
   - 选择了一级指标时，二级指标为必填。
2. **批改方式名称统一为“仅人工批改”**：任务详情里不再显示“教师手动批改”。
3. **新提交通知**：没有重交时不再出现“（含 0 份重交）”。
4. **添加班级弹窗**：添加成功后，下拉浮层不再残留在页面上。

## 四、学生

1. **任务中心显示“未解锁”**：尚未解锁的中级、高级任务显示“未解锁”，操作改为“查看解锁条件”，鼠标悬停可以看到原因。已经提交过的任务照常显示原状态和“查看”入口。
2. **修改初始密码页**：首次登录时页面不再发灰。

## 五、管理员与通用界面

1. **新建用户弹窗**：
   - 标题按对象显示，例如“新建学生”“编辑教师”；
   - 密码框提示“请输入初始密码（4–16 位）”。
2. **个人中心**：手机、邮箱、性别改为选填，可以只修改姓名，也可以清空手机号或邮箱。
3. **用户管理**：内置管理员的“用户类型”显示为“管理员”，此前显示为“教务管理”。
4. **班级列表**：操作列收窄，组织树在 1536 像素以下宽度时变窄，“学制”等列不再被遮住。教师、学生列表去掉了每行都相同的“用户类型”列。
5. **学期收尾弹窗**：离开页面时自动关闭；正在归档时会阻止离开。
6. **通知列表**：“已读”“删除”按钮不再压住长文字。

## 六、数据库变更（V19）

V19 只修改数据，不改表结构，可以重复执行：

- 教师角色获得“绑定课程”（`edu:class-course:bind`）按钮权限；
- 学院教务管理员的数据范围改为“本部门及以下”，授予组织查询、班级管理、师生管理与导入导出等 18 个菜单；从 `edu.role.admin-codes` 中移除 `college_admin`；
- 更新新提交通知模板的内容和参数；
- 字典“用户类型”值 0 的名称改为“管理员”；
- 停用“通知公告”菜单；
- 软删除从未使用过的“解绑课程”按钮菜单（5065）；
- 班级课程表中旧的助教逗号列**保留**（本版停止写入，下个版本再删除），以保证可以回退到 V1.0.1.7。

## 七、部署相关

1. MySQL 健康检查不再在命令行参数里传递密码。
2. 全量安装包的数据库基线升到 19。

## 八、升级步骤

升级步骤与 V1.0.1.7 相同。在服务器上解压增量包后执行：

```bash
sudo ./upgrade.sh
```

- 升级完成后，请执行 `sudo nusctl status`，确认各服务健康。
- 如需回退：执行 `sudo nusctl rollback previous`。数据库会恢复到升级前的备份。

## 九、补充修复（2026-10-10）

1. **账号的邮箱、手机号没有改动时，保存不再提示“邮箱已经存在”**：
   - 历史数据里可能有多个账号用了同一个邮箱或手机号（例如早期导入时留下的重复数据）。此前，只要邮箱重复，这个账号的任何修改都保存不了。现在，邮箱、手机号与该账号原来的值相同时，直接覆盖保存。
   - 改成别人正在用的邮箱或手机号时，提示会写明被哪个账号占用，例如“邮箱已被账号「20011031」（王老师）使用”；占用账号已停用的，也会注明“已停用”。
   - 导入覆盖更新同样按这个规则处理。
2. **教师、学生、用户列表新增“邮箱”列**。
3. **学生导入模板改为按班级导入**：
   - “学生档案”工作表的表头改为：学号*、姓名*、性别、班级*、手机号、邮箱、状态；
   - “班级”列从现有班级中下拉选择；导入时按班级自动补全学生的专业和入学年份，并自动把学生加入该班级；
   - 原来的“主专业编码”“入学年份”两列已删除。**旧版学生模板不能再使用，请重新下载模板**；
   - 一名学生加入多个班级，或跨专业、跨年级加入班级时，仍然在“班级关系”工作表里填写，并写明备注；
   - 导出的学生名单也按新格式输出，“班级”列写学生的主班级。
4. **大文件导入不再“转完圈没下文”**：
   - 此前点“确认导入”后，页面最多等 30 秒；几百人的导入超过 30 秒时，按钮恢复但看不到结果，导入其实还在进行。
   - 现在确认导入改为在服务器后台执行。导入窗口显示“正在导入，共 N 行，已用时 X 秒”，完成后自动进入“导入结果”；
   - 导入期间可以点“关闭窗口，后台继续”，导入不受影响，完成后刷新列表即可看到；
   - 导入失败时，窗口里显示原因，数据不会只导入一半；服务重启打断的导入会标记为失败，提示重新上传；
   - 同时加快了预检和导入：本机实测 350 名学生，预检约 1 秒，导入约 50 秒（此前约 130 秒）。
5. **学生首次登录修改初始密码**：
   - 修复右侧修改密码的表单看不见、需要刷新才出现的问题；
   - 修复填好新密码后点按钮没有反应的问题；
   - 页面下方新增“返回登录”，可以退出后换账号登录。
6. **耗时较长的操作不再提前报超时**：班级添加学生、绑定班课、学期归档、复制任务、AI 新建任务确认，以及各类导出，等待时间放宽到 2 分钟。
7. **AI 对话、AI 研判的流式输出**：修复部署后文字要攒一大段才一起出现的问题。
8. **日志中不再记录导入时填写的初始密码**。

## 十、已知限制与后续计划

- 学院教务管理员的课程、任务、统计按学院过滤留到后续版本。原因是统计 SQL 中有在 JOIN 条件里嵌套的子查询，脚手架的数据权限规则覆盖不到这种写法。
- 学生角色的数据权限暂时保持为“全部”（学生端接口已经按登录人过滤）。
- 旧的助教逗号列将在下个版本删除。
- 导入时账号逐行写入，几千人的导入仍需要几分钟（在后台进行，可关闭窗口）；后续版本改为批量写入。
- 班级批量添加学生、AI 新建任务确认、绑定班课时发送的站内通知仍随请求同步发送，后续改为后台发送。
