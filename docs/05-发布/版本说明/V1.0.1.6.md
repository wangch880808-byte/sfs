# 师砺平台 V1.0.1.6 增量更新说明

适用范围：已安装 V1.0.1.5（Flyway 版本 16）的离线环境，升级后 Flyway 版本为 17。从 V1.0.1.3、V1.0.1.4 直接升级同样可行（升级时依次执行尚未执行的迁移），但请同时阅读 V1.0.1.4、V1.0.1.5 的更新说明，其中的“升级前必读”同样适用。

本版是界面与交互的整体重做，参照 ScholarOS 的视觉与交互标准：配色、字号、圆角、页面骨架、状态显示、空状态与确认框全站统一；导航按角色重新编排；界面、通知与报错的叫法按术语表统一。业务流程与数据不变（数据库只改菜单、字典、通知模板的显示名称，并补两处授权，见“六、数据库变更”）。

## 一、升级前必读

1. **界面整体改版，默认深色**：
   - 浏览器里缓存的旧主题设置（主色、圆角、布局等）会在首次打开时自动复位；各人选择的深色或浅色保留。
   - 取消了右上角的“偏好设置”面板（配色与布局由平台统一）；顶栏仍可切换深浅色。
   - 登录页去掉了换主题色与切换布局的按钮。
2. **导航重新编排（菜单管理、页面地址、权限都不变）**：
   - 教师：工作台｜教学（实训课程管理、课程资源、题库管理）｜实训任务管理｜学情（教学过程分析、教学问题研判、评价指标管理）｜留言互动。原来的“教师工作台”与“工作台”内容相同，已从导航中去掉，地址仍可打开。
   - 学生：改为顶部导航——工作台｜我的课程｜任务中心｜能力（能力分析、单项能力评测）｜我的留言｜校园资讯；“个人中心”移到右上角头像菜单；学生端不再显示页签栏。
   - 管理员等其他角色仍按“菜单管理”中的原树显示。学校在菜单管理里新增、授权给教师或学生的菜单会出现在“其他”分组里，不会丢。
3. **叫法统一**：界面、通知、报错与导出表头里的叫法按术语表统一（见“三、术语对照”）。学校改过名称的菜单、字典与通知模板保持不变，只更新仍是出厂默认的部分。
4. **导入模板表头变化**：题库导入模板的“一级/二级技能指标”改为“一级/二级能力指标”，“技能等级”改为“任务等级”，“班级 ID”改为“班级编号”。之前下载的旧模板仍可直接导入。

## 二、界面与交互

1. **首页改为“现在要处理什么”**：
   - 教师：待批改（按任务分组，等得最久的在前，点开直接进入批改）、即将截止、我的课程、学生留言、最近提交。
   - 学生：待完成（打回重做、未解锁的任务会标出）、最新反馈、通知、我的课程与进度。
   - 管理员：全校概况、提交与批改（含“AI 批改”数）、成绩分布、需要关注的事项；去掉了“趋势图待接入后端数据”占位。
   - 每块内容单独加载，某一块读取失败只影响它自己，并可单独重试。
2. **批改页改为专注的工作区**：左侧学生列表（筛选、搜索、键盘切换），右侧作答、附件、评分与评语、AI 初评；底部固定“打回重做”“应用 AI 初评”“保存批改”。批量生成 AI 初评、导出与导入成绩册在页头。
3. **未解锁的任务不再是空白页**：学生打开未解锁的任务时，页面说明原因、解锁条件，以及在哪里查看等级进度。
4. **状态统一显示为“圆点＋文字”**：同一种状态在各页面写法一致（如“已退回”统一为“已打回”）；颜色只用于提示该注意的事。
5. **空状态、加载与出错**：
   - 空状态分三种：还没有数据、筛选没有结果（可一键清除筛选）、前置条件不满足；
   - 加载提示写明在读什么；
   - 出错按“什么没成功—原因—下一步”写，填好的内容保留。
6. **确认框**：归档、停用、打回、删除、批量操作等的确认写明对象、后果和怎么恢复；确认按钮重复动作名，取消按钮统一为“返回”。归档、停用可以恢复，不再用红色；红色只留给删除等不能恢复的操作。移出班级学生、删除聊天角色改为先确认。
7. **深色模式**：所有文字与背景的对比度达到 WCAG AA（4.5:1）；深色下弹窗遮罩加深；主按钮在深色下用较深的蓝底，白字清楚。
8. **其他**：两个汉字的按钮不再自动插入空格（“返回”不再显示成“返 回”）；表格文字左对齐、数字右对齐；表单、对话框、抽屉的样式与间距统一。

## 三、术语对照

| 以前的写法 | 现在的写法 |
|---|---|
| 作业 | 实训任务（菜单、标题）／任务（正文、按钮） |
| 评阅、AI 批改（指 AI 给出的分数与评语） | AI 初评（教师确认后才是成绩） |
| 退回 | 打回（学生需要重做） |
| 站内信、消息（指系统提醒） | 通知 |
| 会话、消息（指师生之间的问答） | 留言 |
| 技能（指学生的能力） | 能力 |
| 新增 | 新建（加入已有的班级、学生等用“添加”） |
| 您 | 你 |

## 四、问题修复

1. 教师打开“留言互动”时课程下拉为空、提示没有权限：给拥有“留言互动”的角色补上“查询班课”只读权限。
2. 班级课程列表中课程名显示成“课程1”这类编号：接口补上课程名（同时减少了逐行查询）。
3. 学校教务管理员看不到“管理员看板”菜单：补上缺失的上级目录授权。
4. 模型停用提示把占位符原样显示为“({})”。
5. 错误日志标记处理时，确认文字总写“已处理”。
6. 课程资源上传对话框占满整个屏幕宽度。
7. AI 对话回复失败后“思考中”占位一直不消失；改为在输入区上方说明原因并可重试。
8. 深色主题下弹窗遮罩偏淡（1.0.1.4 遗留）。

## 五、下线与调整

- 右上角“偏好设置”面板、登录页的主题色与布局切换按钮。
- AI 对话页头部没有功能的下载按钮。

## 六、数据库变更（V17，自动执行，可重复执行）

V17 只改显示名称与授权，不改表结构与业务数据（课程、任务、成绩、学院、评价指标等不动）。每一处只在仍是出厂默认值时才修改，学校改过的名称保持原样。

- **菜单（38 个）**：
  - 按钮与页面的“新增”“创建”改为“新建”（如“用户新增”→“用户新建”、“创建任务”→“新建任务”）；
  - “消息中心”→“通知中心”，“站内信管理”→“通知管理”，“站内信模板”→“通知模板”，“消息记录”→“通知记录”；
  - “查询/提交/批改作业”→“查询/提交/批改任务”；
  - AI 评阅权限组→“AI 辅助”，其中“AI 批改”→“AI 初评”；“AI”与中文之间、“SQL 与连接池监控”补上空格。
- **字典**：
  - 类型名称“登陆”→“登录”，“站内信模版的类型”→“通知模板的类型”，“EDU 作业类型/等级/状态”→“实训任务类型/等级/状态”；
  - 字典数据“新增”→“新建”、“系统消息”→“系统通知”；字典值不变。
- **教学通知模板（11 个）**：名称与内容中的“作业”改为“任务”（如“新作业发布”→“新任务发布”），任务名改用「」标注，分数后加“分”，两个留言模板改写得更清楚；模板编号、参数与占位符不变。
- **授权修复**：
  - 拥有“留言互动”的角色补上“查询班课”（只读）。在本地基线上是教师角色获得该权限，可以调用“按班级查询课程”接口。
  - 角色有已授权的页面却缺少上级目录时补上目录（只补目录，不补页面和按钮）。在本地基线上是学校教务管理员补上“能力培养”目录，从而能看到已授权的“管理员看板”。
- **升级时清理缓存**：除菜单与权限缓存外，一并清理通知模板缓存，新叫法立即生效。

## 七、升级步骤

1. 将升级包复制到服务器，执行 `sha256sum -c` 校验压缩包。
2. 解压后在包目录执行：`sudo ./upgrade.sh "$PWD"`。
   脚本会自动：
   - 备份 `.env` 与数据库；
   - 构建新镜像；
   - 执行 V17；
   - 清理菜单、权限与通知模板缓存；
   - 依次启动后端和前端并检查健康状态。
3. 升级后执行 `nusctl status`、`nusctl doctor`，并用教师、学生、管理员账号登录，检查常用页面。
4. 提醒使用者：首次打开新版本时浏览器会自动复位旧的主题缓存；如个别页面样式异常，强制刷新一次即可。

## 八、回滚

1. **恢复数据库**：`nusctl restore <升级时生成的备份文件>`（V17 无法自动回退）。
2. **恢复旧镜像标签**：用 `/srv/nus/config/.env.before-V1.0.1.6-<时间>` 恢复 `.env`，把镜像标签改回上一版本。
3. **重新启动服务**：将 `/srv/nus/current` 指回上一版本的发布目录后，执行 `docker compose up -d`。

## 九、升级后需要学校确认的事项

1. **通知学生**：学生端改为顶部导航，“个人中心”在右上角头像菜单。
2. **自定义过的名称**：学校改过名称的菜单、字典和通知模板没有被修改，如需与新叫法一致，请在“菜单管理”“字典管理”“通知模板”中自行调整。
3. **教师的学情页面**：“教学过程分析”“教学问题研判”默认没有授权给教师；如需开放，在“角色管理”中为教师勾选。

## 十、已知问题

1. **学生角色的数据范围仍为“全部”**（1.0.1.5 已说明）：本版专注界面改版，未调整，计划在后续版本处理。
2. **“教师可读取管理员看板汇总”“权限码共用”**（1.0.1.4 遗留）仍保持原状。
3. **教师端“学生留言”卡片**：后端暂无“教师跨班级未读留言”接口，首页卡片按“收到学生留言”的通知列出，未读数取自看板统计。
