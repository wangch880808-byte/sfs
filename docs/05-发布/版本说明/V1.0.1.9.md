# 师砺平台 V1.0.1.9 增量更新说明

**适用范围**

- 已安装 V1.0.1.8 或 V1.0.1.8.1（Flyway 版本 19）的离线环境，升级后 Flyway 版本为 20。
- 从更早版本升级时，会依次执行中间各版本的迁移，请同时阅读对应版本的更新说明。

本版主要解决两个问题：

- 操作成功后页面没有马上更新；
- 学生、任务多了以后查询变慢。

另外修正了管理员、课程负责人打不开别人布置的任务的问题。界面风格不变。

## 一、升级前必读

1. **只调整索引和统计信息，不改数据**：数据库迁移 V20 只调整索引，并为状态类字段建立统计直方图，可以重复执行。数据量在几万条提交以内时，只需几秒，不明显延长停机时间。
2. **新增缓存**：系统参数、当前学期、能力指标、字典数据会缓存一段时间。
   - 在系统界面里修改这些内容时，缓存会立即清除，修改马上生效；
   - 直接改数据库时，最多要等缓存过期（参数 60 秒、学期 10 分钟、指标和字典 1 小时）才会看到新值；
   - 升级、恢复备份时，脚本会自动清除这些缓存。
3. **升级后请重新登录**，以加载新的菜单和权限。

## 二、操作后马上更新

1. **课程详情添加班级**：点确定后，班级列表、班级数和任务覆盖的班级数立刻更新。如果新加的班级不在当前筛选里（默认只看“进行中”），页面会自动改为显示全部班级，并给出提示。
2. **右上角铃铛**：在“我的通知”或学生首页把通知标为已读后，铃铛上的未读数立刻减少，不用再等半分钟。
3. **删除后页码回退**：在题库、学生管理弹窗以及各个列表里，删掉或移出某一页的最后几条后，自动回到上一页，不再显示空白页。

## 三、查看别人布置的任务

管理员、课程负责人和课程团队成员可以打开别人布置的任务，查看：

- 任务详情、提交情况和成绩；
- 个别延期名单；
- 批改页，并导出成绩册。

页面会注明“只能查看”，批改、打回、延期、催交等操作仍由布置者完成。课程详情的任务列表里：

- 不是自己布置的任务，“编辑”“归档”按钮不再显示；
- “批改”显示为“查看提交”。

此前这些情况会提示“实训任务不存在”。

## 四、查询提速

本机实测数据规模：6000 名学生、2400 个任务、8.4 万条提交，模拟多个学期的积累。下表为同一台机器上改前、改后的对比。

| 页面 | 数据库查询次数 | 响应时间 |
| --- | --- | --- |
| 课程详情 | 约 125 次 → 13 次 | 约 220 ms → 70–90 ms |
| 提交记录、批改列表 | 约 100 次 → 7–8 次 | 160–540 ms → 25–50 ms |
| 班课详情 | 约 90 次 → 13 次 | 110–140 ms → 45–55 ms |
| 课程分析 | 21 次 → 4 次 | 40 ms → 20 ms |
| 登录、刷新页面时读取权限 | 扫描约 6000 行 → 约 450 行 | 不变 |

**2 万名学生的规模**（约 8000 个任务、28 万条提交、60 万条站内信）：

- 上述页面的查询次数不随数据量增加；
- 学生“我的任务”、教师任务列表、教师看板借助新建的统计直方图，分别为 17 ms、14 ms、29 ms。

**其他改进**：

- 教师留言、学生首页、学生课程列表的逐条查询改为批量查询；
- 班级批量加学生、移出学生时，任务分配和站内信改为批量写入；
- 截止提醒和成绩册导入不再逐条查询；
- 系统参数、当前学期、能力指标和字典数据加了缓存。

## 五、数据库变更（V20）

只调整索引，可以重复执行：

- **新增**：
  - 用户表：按用户类型、组织、手机号、邮箱查询的索引；
  - 用户角色表：按用户、按角色查询的索引；
  - 用户资料表：按年级查询的索引；
  - 参数表：按参数键查询的索引；
  - 提交表：按任务与成绩、按状态、按学生与批改时间查询的索引；
  - 任务表：按布置者与状态查询的索引；
  - 留言表：按类型与已读状态查询的索引。
- **删除**：4 个被新索引完全覆盖的旧索引（提交表 2 个、任务表 1 个、留言表 1 个）。
- **统计直方图**：为用户、班级、课程、任务、提交、留言、站内信等表的状态和删除标记字段建立直方图，帮助数据库选择正确的查询顺序。
- 全量安装包的数据库基线升到 20。

## 六、升级步骤

在服务器上解压增量包后执行：

```bash
sudo ./upgrade.sh
```

- 已安装 V1.0.1.8 或 V1.0.1.8.1 的服务器都可以直接升级，不需要先回滚。
- 升级完成后执行 `sudo nusctl status`，确认各服务健康。
- 如需回退：执行 `sudo nusctl rollback previous`，数据库会恢复到升级前的备份。

## 七、已知限制

- 导入账号时仍逐行创建账号，几千人的导入需要几分钟（在后台进行，可以关闭窗口）。
- 学生名单、成绩册等导出接口仍一次读出全部数据。
