# 新人上手：第一周

> 面向：刚接手项目的学生，以及帮他们干活的 AI 智能体。
> 适用版本：V1.0.1.10
> 最后核对：2026-10-14

目标：一周后能在本机跑起项目、跑通全部校验，独立完成并提交一个小改动。

每天结束时，把遇到的问题和文档里讲不清的地方记下来，第 5 天一起提给指导老师，或直接改文档。

## 第 1 天：读文档

按顺序读，不用一次全懂：

1. [README](../../README.md)：项目做什么、目录结构。
2. [当前状态](当前状态.md)：线上版本、已知问题。练习任务就从这里挑。
3. [AGENTS.md](../../AGENTS.md)：第 4 节“不可违反的规则”和第 6 节“必须先问人再做”。**人也要遵守。**
4. [协作约定](../../CONTRIBUTING.md) 和 [开发流程](../03-开发/开发流程.md)：分支、提交信息、PR。**`dev`、`master` 只有指导老师能推送和合并，你的改动只能通过 PR 提到 `dev`。**
5. [术语表](../01-产品/术语表.md)：认领、封存、删除、班课、公共课、待发布。
6. [架构概览](../02-架构/架构概览.md)、[权限与数据范围](../02-架构/权限与数据范围.md)：先看图和小标题。
7. [用户操作手册](../01-产品/用户操作手册/用户操作手册.md)：挑“教师”“学生”两部分浏览，知道用户每天做什么。

当天顺手做：
- 在 Gitee 配好自己的 SSH key，克隆主仓库（做小程序的同学再克隆 `shili-miniapp`）；
- 按 [环境搭建](../03-开发/环境搭建.md) 装好 JDK 17、Maven 3.9、Node ≥ 20.19、pnpm 10、Docker，以及 gitleaks。

## 第 2 天：跑起来，用各角色看一遍

按 [环境搭建](../03-开发/环境搭建.md) 操作，概要如下（在仓库根目录执行）：

```bash
# 1. 打后端 jar（local-env.sh 默认用 NUS-backend/nus-server/target/nus-server.jar），约 3 分钟
#    只装了 mvnd 的，把 mvn 换成 mvnd，参数相同
cd NUS-backend && mvn -q -DskipTests package -pl nus-server -am && cd ..

# 2. 起本机一次性 MySQL、Redis 和后端（只绑定 127.0.0.1）
deploy/tests/e2e/local-env.sh up
deploy/tests/e2e/local-env.sh bootstrap
deploy/tests/e2e/local-env.sh backend

# 3. 灌演示数据：一个教师、三个学生、一门课程、四个任务和几份提交
NUS_E2E_BASE_URL=http://127.0.0.1:48280 python3 deploy/tests/ui/seed_demo.py

# 4. 起前端（另开终端），浏览器打开 http://localhost:5666
cd NUS-front && pnpm install && NUS_DEV_API_TARGET=http://127.0.0.1:48280/admin-api pnpm dev:antd
```

账号口令都是随机生成的，只存在本机：
- 管理员 `admin` 的口令在 `~/.cache/nus-e2e/admin.pw`；
- 演示账号（`demoteacher`、`demostudent1`～`demostudent3`）的口令在 `~/.cache/nus-e2e/demo-accounts.json`。

分别登录看一遍，每个角色至少做一件事：

| 角色 | 账号 | 看什么 |
| --- | --- | --- |
| 超级管理员 | `admin` | 用户管理、班级、课程、学期；AI 大模型菜单；管理员看板 |
| 教师 | `demoteacher` | 课程详情的班级页、任务页（负责人列、显示已封存）；批改一份待批改的提交；教学过程分析 |
| 学生 | `demostudent1` | 待办任务、提交一次、看教师反馈和打回 |
| 学校教务管理员、学院教务管理员、课程负责人 | 演示数据里没有 | 用 `admin` 在用户管理里新建，分配对应角色后登录看看，体会数据范围的区别 |

用完执行 `deploy/tests/e2e/local-env.sh down`。数据库在内存里，down 之后数据全部消失，下次重新 up。

**卡住了**：先看 `~/.cache/nus-e2e/logs/` 下的后端日志，再查 [故障排查](../04-运维/故障排查.md)，还不行就记下来问人。

## 第 3 天：跑通全部校验和一套 e2e

```bash
# 全部检查：敏感信息扫描、后端单测、前端类型检查和单测、迁移检查、权限矩阵
scripts/check-all.sh --all
```

- 全部跑完约 9 分钟。判断成败只看末尾的“结果”汇总，中间的警告和长报告见 [环境搭建](../03-开发/环境搭建.md) 的“正常的输出噪音”。
- 迁移和基线都没改动时，汇总里会显示“跳过 迁移检查 check-v21”，这是设计如此，不是漏跑。要单独验证 V21，得传入基线 20 文件（新仓库里没有，找指导老师要），写法见 [测试指南](../03-开发/测试指南.md) 第 6 节。
- 迁移检查和权限矩阵需要 Docker；暂时没有 Docker 时加 `SKIP_DOCKER=1`，但发版前必须跑全。
- 后端单测依赖时区，脚本已带 `TZ=Asia/Shanghai`；自己单独跑 mvn 时别忘了。

然后在本机一次性环境上跑一套 e2e（先按第 2 天把环境 up 起来，再 bootstrap、backend）：

```bash
export NUS_E2E_BASE_URL=http://127.0.0.1:48280
export NUS_E2E_ADMIN_USERNAME=admin
export NUS_E2E_ADMIN_PASSWORD_FILE=~/.cache/nus-e2e/admin.pw
python3 deploy/tests/e2e/e2e_v10110.py --dry-run
python3 deploy/tests/e2e/e2e_v10110.py
```

- 每个场景输出 `PASS` 或 `FAIL`，最后汇总，有失败时退出码非零。
- 4 套 e2e 的前置条件、场景说明见 `deploy/tests/e2e/README.md` 和 [测试指南](../03-开发/测试指南.md)。
- **e2e 只能对本机跑。** 脚本会造数据、切换当前学期，绝不能指向学校服务器或测试服务器。

第 3 天结束时，能说清楚：改了后端要跑什么、改了前端要跑什么、改了 SQL 还要加跑什么。

## 第 4–5 天：练习任务

从下面两个任务里选一个；时间够就两个都做，按顺序。

做法和正式开发一样：
1. 在 Gitee 建 Issue 登记；
2. 从最新的 `origin/dev` 拉分支（`git fetch origin && git switch -c fix/简述 origin/dev`）；
3. 先写一个能复现问题的测试；
4. 改代码；
5. 跑 `scripts/check-all.sh`；
6. 更新 `CHANGELOG.md` 的“未发布”一节；
7. 提 PR，目标分支选 `dev`，审查人、测试人选指导老师；等指导老师本地测试后合并，被打回就在同一分支修改再推送。步骤见 [开发流程](../03-开发/开发流程.md)。

### 任务一：课程分析里同分学生按学号排序（后端，易）

**背景**：[当前状态](当前状态.md) 的已知问题“课程分析里同分学生的先后顺序不固定”。

“教学过程分析”页的“最高分”“最低分”只显示每个任务排第一的学生。几个学生同分时，显示谁是随机的，刷新一下可能就变了。

**要改的地方**：`NUS-backend/nus-module-edu/src/main/resources/mapper/statistics/StatisticsMapper.xml` 里的 `selectHomeworkStudentExtremes`。

- 两个窗口函数目前只按分数排序：
  - `ROW_NUMBER() OVER (PARTITION BY hr.homework_id ORDER BY hr.score DESC) AS topRank`
  - `ROW_NUMBER() OVER (PARTITION BY hr.homework_id ORDER BY hr.score ASC) AS lastRank`
- 两处都在分数后面加第二排序：学号升序。学号就是 `system_users.username`（`su` 已经 JOIN 进来了）。
  - 写法：`ORDER BY hr.score DESC, su.username ASC`、`ORDER BY hr.score ASC, su.username ASC`。
  - 学号相同的情况理论上不存在；稳妥起见可以再加 `hr.student_id` 作第三排序。
- 改上方的注释。它现在写着“只按分数编号……不能改为 RANK 或加入时间排序”。改成：按分数编号，同分按学号；仍然只取 5 个，不能改成 RANK，不能按时间排。
- 同文件里的 `selectHomeworkTopStudents`、`selectHomeworkLastStudents` 是旧的单任务查询，课程分析已不再调用（`EduStatisticsServiceImpl.getCourseAnalysis` 只用 `selectHomeworkStudentExtremes`）。可以顺手加上同样的第二排序保持一致，也可以不动，在 PR 里写明。
- Java 代码不用改。`EduStatisticsServiceImpl.buildRankedStudentScores` 按 SQL 给出的编号排序，编号确定了，结果就确定了。

**测试**：`NUS-backend/nus-module-edu/src/test/java/cn/nus/zknu/module/edu/dal/mysql/statistics/StatisticsMapperPerformanceSqlTest.java`。它用 H2 走真实的数据权限拦截器链。

1. 测试里建的 `system_users` 表没有 `username` 列。先在 `setUp` 的建表语句里加上，并给已有的 INSERT 补学号值，否则改后的 SQL 会报列不存在。
2. 新增一个测试：同一任务里 3 个学生同分（例如 90 分），学号故意和 `student_id` 的顺序相反；断言 `topRank` 的顺序按学号升序，且多次执行结果一样。最低分方向同样断言。
3. 跑已有的 `windowsMatchLegacyScoresAndStudentsExceptUnspecifiedTieOrder` 和 `boundaryTiesAndNullScoresStillReturnExactlyFiveWithoutExpandingTies`，确认仍然通过：取到的分数和人数不能变，只是同分的先后确定了。

```bash
cd NUS-backend
TZ=Asia/Shanghai mvn -q test -pl nus-module-edu -am \
  -Dtest=StatisticsMapperPerformanceSqlTest -Dsurefire.failIfNoSpecifiedTests=false
```

**完成标准**：
- [ ] 新测试先失败（改 SQL 前），改后通过；
- [ ] `StatisticsMapperPerformanceSqlTest`、`EduStatisticsCourseAnalysisTest` 全部通过；
- [ ] 改了复杂 SQL，按 `NUS-backend/AGENTS.md` 跑一次 db-it（真实 MySQL）通过；
- [ ] `scripts/check-all.sh` 通过；
- [ ] 本机实测：用演示数据把两名学生批成同分，“教学过程分析”页多次刷新，最高分学生不再变化；
- [ ] `CHANGELOG.md` 的“未发布”一节写一行；`当前状态.md` 里删掉这条已知问题；
- [ ] PR 说明里写：没有数据库结构变化、没有权限变化。

### 任务二：最高分、最低分并列时显示人数（前端，中）

**背景**：任务一做完后，同分时显示的是学号最小的那位。但老师看到“李晓雨 95 分”，不知道其实有 3 个人都是 95 分。

**目标**：在“教学过程分析”页（`NUS-front/apps/web-antd/src/views/edu/statistics/teaching-process.vue`）的任务表“最高分”“最低分”两列，以及上方“表现最佳任务”摘要里，有并列时显示为“李晓雨 等 3 人 95 分”。

**要改的地方**：
1. 把 `teaching-process.vue` 里的 `normalizeCourseAnalysis` 函数抽到同目录的新文件，例如 `course-analysis.ts`。前端规则要求纯逻辑抽成 `.ts` 并写 vitest 测试。
2. 计算并列人数：数 `top5` 里和 `top5[0].score` 相同的人数。`last5` 同理。
3. 接口每个方向最多返回 5 人，5 人全部同分时，实际并列的可能更多。这时显示“等 5 人以上”，不要显示成“等 5 人”。
4. 返回的数据加 `topTieCount`、`lowTieCount` 两个字段。页面在姓名后面显示“等 N 人”，只有 1 人时不显示。
5. 接口没有数据（`top5` 为空）时照常显示“-”。
6. 不改后端接口。`teaching-issue.vue` 也读 `top5`、`last5`，但只用分数，不受影响，不用改。

**测试**：新建 `course-analysis.test.ts`，写法参考同目录的 `chart-kit.test.ts`。至少覆盖：
- 无并列；
- 2 人并列；
- 5 人全部同分；
- `top5` 为空；
- 旧格式数据（`payload.items`）照常转换。

```bash
cd NUS-front
pnpm test:unit
pnpm check:type
npx eslint apps/web-antd/src/views/edu/statistics/course-analysis.ts apps/web-antd/src/views/edu/statistics/teaching-process.vue
npx prettier --check apps/web-antd/src/views/edu/statistics/course-analysis.ts apps/web-antd/src/views/edu/statistics/teaching-process.vue
```

**完成标准**：
- [ ] 新单元测试覆盖上面 5 种情况，全部通过；
- [ ] `pnpm check:type`、`pnpm test:unit`（含 `tests/copy` 文案扫描）通过，eslint、prettier 无告警；
- [ ] 文案符合 `NUS-front/docs/ui-copy.md`；新增的“等 N 人”“等 5 人以上”在浅色、深色模式下都清楚可读；
- [ ] 浏览器实测：用演示数据造出无并列、2 人并列两种情况各截一张图，附在 PR 里；
- [ ] `CHANGELOG.md` 的“未发布”一节写一行；
- [ ] `scripts/check-all.sh` 通过。

## 和 AI 智能体协作

### 开始前

- 让它先读 `AGENTS.md` 和 `docs/06-交接/当前状态.md`。在后端、前端目录工作时，再读对应目录的 `AGENTS.md`。Claude Code 会通过 `CLAUDE.md` 自动读取，其他工具要在第一句话里明确要求。
- 一次只给一件事，说清楚范围。例如“只改 `StatisticsMapper.xml` 的这一条 SQL 和对应测试”，不要说“优化一下统计”。
- 让它先说计划：改哪些文件、加什么测试、怎么验证。你确认后再动手。

### 要求它跑校验

- 改完必须跑 `scripts/check-all.sh`，把结果原样贴出来。只说“应该能过”不算。
- 涉及数据库、权限、跨端流程的，要求按 [测试指南](../03-开发/测试指南.md) 加跑 db-it 或 e2e。
- 它说某个测试“与本次改动无关所以失败”时，自己在 `dev` 上跑一遍，确认确实原来就失败。

### 审它的改动

逐个文件看 diff，重点看：

- 有没有违反 `AGENTS.md` 第 4 节：改了已发布的迁移、手写 SQL 漏了 `deleted = 0`、接口权限变了没更新快照、提交了口令或真实数据；
- 有没有改了任务范围以外的文件，特别是悄悄改测试的期望值让测试“通过”；
- 新逻辑有没有测试，测试是否真的会在修改前失败；
- 界面文字是否符合术语表，例如“封存”不能写成“归档”；
- 文档是否同步：`CHANGELOG.md`、用户手册、`当前状态.md`。

看不懂的地方让它解释“为什么这样改”，解释不清就不合并。

### 不能让它直接做的事

下面这些即使它说“我可以做”，也要你先确认，有的要指导老师确认（详见 `AGENTS.md` 第 6 节）：

- 连接或操作学校服务器、测试服务器，包括只读查询；
- 新增迁移、改表结构、删除数据或文件；
- 推送 `dev`、`master`，合并 PR（只有指导老师能做）；打标签、构建正式升级包；
- 改角色、权限点、菜单；
- 引入新依赖或升级大版本；
- 回滚线上版本；
- 把任何口令、key、AppSecret 粘贴给它。它需要连本机环境时，让它从 `~/.cache/nus-e2e/` 的文件读取。

### 收尾

会话结束或提 PR 时，让它更新 `docs/06-交接/当前状态.md`：做了什么、没做完什么、下一步、注意事项。下一个人或下一个智能体从这里接着做。
