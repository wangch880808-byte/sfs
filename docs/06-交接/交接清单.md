# 交接清单

> 面向：指导老师（交出方）和接手的学生（接收方），交接时逐项打勾。
> 适用版本：V1.0.1.10
> 最后核对：2026-10-14

**本文件只列项目，不写任何口令、地址、账号值。** 口令和账号一律通过下面“交接方式”一栏说的渠道传递，不进 git、不发群聊、不写进 Issue。

交接方式约定：
- **当面**：当面口述或在交接人电脑上查看，接收方自己录入密码管理器；
- **密码管理器共享**：用学校或团队的密码管理器共享条目（推荐）；
- **平台内操作**：在对应平台里直接把接收方加为成员或管理员，不传口令。

“谁负责”一栏交接前填好姓名或岗位，交接后改成接收方。

## 8. 交接后要做的事

交接完成后一周内做完，做完在这里打勾并写日期。

| ☐ | 事项 | 怎么做 | 谁负责 |
| --- | --- | --- | --- |
| ☐ | 更换交接中暴露过的口令 | 凡是交接时口述、屏幕共享、临时文件里出现过的口令都换掉：平台管理员口令、服务器账号口令、AI key、AppSecret。数据库和 Redis 口令要改时按 [运维手册](../04-运维/运维手册.md) 操作，**不能改 `NUS_MYBATIS_ENCRYPTOR_PASSWORD`** | 接收方 |
| ☐ | 停用交出方的个人账号 | 交出方不再参与的，停用其服务器账号、平台管理员账号、Gitee 写权限、小程序开发者身份 | 指导老师 |
| ☐ | 确认备份正常 | 在学校服务器执行 `sudo nusctl backup`，再 `ls -lh /srv/nus/backups/`，确认有新文件和对应 `.sha256`；确认定时备份和异地拷贝在运行（见运维手册） | 接收方 |
| ☐ | 做一次恢复演练 | **在测试服务器或本机一次性环境上做，不在学校服务器上做**：拿学校服务器最新备份，用 `sudo nusctl restore <备份文件>` 恢复，登录平台核对用户数、任务数、最新提交时间 | 接收方，指导老师在场 |
| ☐ | 更新本清单 | “谁负责”一栏改为接收方姓名；“待确认”项补上或标“不适用” | 接收方 |
| ☐ | 更新当前状态 | 在 [当前状态](当前状态.md) 记录交接完成日期和遗留事项 | 接收方 |
