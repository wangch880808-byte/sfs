# 权限与数据范围

- 面向：接手开发的同学和 AI 智能体；需要给学校配置角色的同学
- 适用版本：V1.0.1.10（数据库迁移 V21）
- 最后核对日期：2026-10-14

平台的权限分三层，缺一层都会出安全问题：

1. **功能权限**：有没有这个菜单、按钮（权限点），接口上用 `@PreAuthorize` 判断。
2. **数据范围**：能看哪些学院的班级和用户，由数据权限拦截器自动加条件。
3. **业务归属**：这门课、这个班、这个任务是不是你的，在 Service 里显式判断（`EduDataScopeService`、`EduAiBusinessAccessService`、`HomeworkWriteAccess`）。

## 1. 角色

基线里内置 5 个角色（`system_role`）：

| ID | 名称 | 编码 | 数据范围 `data_scope` | 能做什么 |
| --- | --- | --- | --- | --- |
| 1 | 超级管理员 | `super_admin` | 1 全部 | 拥有全部权限点（`PermissionServiceImpl` 对超级管理员直接放行）；提示词管理、调用日志、学期收尾等只授予它 |
| 159 | 学校教务管理员 | `school_admin` | 1 全部 | 学校层面的查看与审批：组织管理、用户查询、班级查询、管理员看板，课程与指标查询、**公共课审批**（`capacity:course:audit`，V18）。写操作只有组织增删改、公共课审批和以管理者身份给学生留言；完整清单以权限矩阵为准 |
| 160 | 学院教务管理员 | `college_admin` | 4 本部门及以下 | 只维护本学院：组织查询、班级的新建修改封存与学生管理、师生账号的新建导入修改停用恢复重置密码、导出本学院用户（V19，18 个菜单）。**不含**课程、任务、统计、公共课审批 |
| 161 | 教师 | `teacher` | 1 全部 | 建课程、给自己的课添加班级（`edu:class-course:bind`）、布置和批改任务、复制、个别延期、催交、留言互动、学情分析 |
| 200 | 学生 | `student` | 1 全部 | 学生端：我的课程、任务中心、提交、能力分析、我的留言 |

截至 V21，权限矩阵 `deploy/database/tests/permissions/expected-role-endpoints.tsv` 中各角色可调用的接口数（含无需权限点的接口）：超级管理员 399、学校教务管理员 105、学院教务管理员 121、教师 170、学生 81。

**“谁是管理员、谁是教师”不写死在代码里**，读参数（V1.0.1.7 起）：

| 参数 | 基线值 |
| --- | --- |
| `edu.role.admin-codes` | `super_admin,admin,school_admin`（V19 移除了 `college_admin`） |
| `edu.role.super-admin-codes` | `super_admin` |
| `edu.role.teacher-code` | `teacher` |
| `edu.role.student-code` | `student` |

- 代码里用 `EduRoleApi.isCurrentUserAdmin()`、`isCurrentUserTeacher()` 判断，`EduDataScopeService.isGlobalAdmin()` 就是前者。
- `admin` 这个编码在基线里没有对应角色，是为学校自建角色预留的。
- 一个账号有多个角色时，界面形态按“管理员 > 教师 > 学生”取；只有纯学生账号使用顶部导航。
- **已知问题**：学生角色的数据范围仍是“全部”。直接改成“仅本人”会让学生端的教师姓名、院系名称显示为空（V1.0.1.5 已知问题），需要先改那几处查询。

## 2. 权限点

### 2.1 写法

- 格式：`模块:资源:动作`，例如 `edu:homework:create`、`edu:class-course:bind`、`capacity:course:audit`、`ai:chat:use`。
- 存在 `system_menu.permission` 上，`type = 3` 是按钮，`type = 2` 是页面。角色通过 `system_role_menu` 拥有菜单。
- 后端接口：

  ```java
  @PreAuthorize("@ss.hasPermission('edu:homework:create')")
  @PreAuthorize("@ss.hasAnyPermissions('edu:class-course:query', 'edu:homework:query')")
  // 学生端：既要是学生，又要有学生端权限点
  @PreAuthorize("@ss.hasRole('student') and @ss.hasPermission('edu:student-homework:query')")
  ```

- 前端按钮：表格操作里写 `auth: ['edu:homework:update']`，脚本里用 `useAccess().hasAccessByCodes([...])`。**前端隐藏按钮只是体验，安全靠后端。**
- 服务层也会直接判断权限点，例如审批人 = 拥有 `capacity:course:audit`（`CapacityCourseApi.isCourseAdmin`），认领入口要求 `edu:class-course:bind`。

### 2.2 历史遗留

- 部分接口共用权限码，例如课程的删除用的是 `capacity:indicator:delete` / `capacity:indicator:create`（V1.0.1.4 已知问题，未整理）。
- 接口名与动作不一致：`/edu/homework/delete` 是**封存**，`/edu/homework/remove` 才是删除，两者都用 `edu:homework:delete`。

## 3. 学院范围怎么生效

只对 `data_scope` 不是“全部”的角色生效，目前就是学院教务管理员。

1. **前提**：学院教务管理员的账号要挂在**学院**节点上（`system_users.dept_id`），班级挂在学院下属的专业上（`edu_class.dept_id`）。账号没设所属学院时提示“账号未设置所属学院，请联系管理员”。
2. **读**：MyBatis-Plus 的数据权限拦截器给 `edu_class`、`system_users`、`system_dept` 自动追加“部门在本学院子树内”的条件，子查询和派生表里也会改写。规则在 `DeptDataPermissionRule`，表在两个模块的 `DataPermissionConfiguration` 里登记。
3. **写**：新建、修改、导入不经过拦截器，由 `UserDeptScopeService`、`EduDeptScopeService` 显式校验：
   - 操作外院数据返回“无权限”；
   - 导入时外院的行在预检中跳过，原因写“不在本学院”（`EduDeptScopeService.OUT_OF_SCOPE_REASON`）。
4. **没覆盖的**：课程、任务、统计还没按学院过滤。原因是统计 SQL 里有 JOIN 的 ON 条件内嵌套的子查询，拦截器改写不到（V1.0.1.8 已知限制）。所以学院教务管理员不授予这些菜单。

写涉及这三张表的手写 SQL 后，用 H2 走真实拦截器链测一遍，参考 `EduClassDataPermissionSqlTest`。

## 4. 课程负责人、课程团队、班课助教

| 身份 | 存在哪 | 范围 | 能做什么 |
| --- | --- | --- | --- |
| **课程负责人** | `capacity_course.teacher_Id` | 一门课 | 维护课程信息和资源；专属课程里管理全部班级和任务；公共课里**只读**查看全部班级和任务 |
| **课程团队成员** | `capacity_course_member` | 一门课 | 专属课程里与负责人相同：添加班级、布置任务、只读查看别人的任务；**公共课里和普通教师一样**，只看自己认领的班 |
| **班课助教** | `edu_class_course_assistant` | 一个班课（某班某课某学期） | 查看这个班级、学生名单、留言和统计；接收学生留言通知；公共课里可做成绩册导入、花名册导入、留言回复 |

共同规则：

- **批改只认任务布置者**（`edu_homework.teacher_id`）。负责人、团队成员、助教、管理员打开别人的任务都只能查看，页面注明“只能查看”（`HomeworkWriteAccess.canGrade`、`EduAiBusinessAccessService.requireHomeworkCorrectionAccess`）。已封存的任务谁都不能批改。
- 只读查看别人布置的任务（详情、提交、成绩、延期名单、导出成绩册）：管理员、课程负责人、课程团队成员可以（V1.0.1.9）；公共课里团队成员不行，见下节。
- 助教不能给班级布置任务：布置要求是课程负责人或团队成员（专属课），或认领人（公共课）。
- 删除任务：只有布置者本人和管理员。
- 旧的逗号 ID 串列（`capacity_course.teach_assistant_ids`、`edu_class_course.assistant_teacher_ids`）不再用于判断，以关联表为准。

## 5. 公共课认领规则

专属课程不受本节影响。依据：[V1.0.1.10 公共课认领计划](../99-历史/计划/PLAN_V1.0.1.10_PUBLIC_COURSE_CLAIM.md)、[V1.0.1.10 版本说明](../05-发布/版本说明/V1.0.1.10.md)，代码在 `EduDataScopeService`。

| 角色 | 认领、放弃 | 看班级 | 布置任务 | 看任务、提交、成绩 | 批改 |
| --- | --- | --- | --- | --- | --- |
| 普通教师、课程团队成员 | 认领未被认领的班；放弃自己的 | 只看自己认领的 | 只能给自己认领的班 | 自己布置的 | 自己布置的 |
| 课程负责人 | 同上 | 全部（只读，标明认领人） | 只能给自己认领的班 | 全部（只读） | 自己布置的 |
| 公共课审批人 | 可以清除任一班的认领 | 全部（只读） | **不能** | 全部（只读） | 自己布置的 |
| 管理员 | 可以清除任一班的认领 | 全部 | 可以 | 全部（只读） | 自己布置的 |
| 任务布置者（已放弃认领） | — | 不再看到该班 | 不能再布置 | 仍能看自己布置的任务 | 仍能批改自己布置的任务 |
| 班课助教 | — | 按班课，看所在班 | — | 按班课 | — |

规则细节：

- 同一班级、同一课程、同一学期只有一位认领人。两人同时认领，只有一人成功（条件 UPDATE + 课程锁）。
- 只能认领**在线公共课**（公共课、审批通过、未封存）。每学期分别认领。
- “添加班级”在公共课里就是认领。认领后补发该教师在本课程本学期“覆盖其他已认领班级”的进行中任务（`EduPublicCourseBackfillService.backfillForClaim`）。
- 公共课的成绩册导入、花名册导入、留言回复：只允许布置者、认领人、班课助教和管理员；负责人、审批人只读。花名册写入用 `validateClassWriteAccess`。
- 留言接收人：认领人和班课助教；班级没人认领时发给课程负责人；团队成员不接收（`EduMessageRecipientResolver`）。
- 判断方法对照：

  | 问题 | 方法 |
  | --- | --- |
  | 是公共课吗 | `isPublicCourse(courseId)` |
  | 能只读看全部吗 | `canViewAllPublic(courseId)` = 管理员 或 审批人 或 课程负责人 |
  | 能给这个班布置吗 | `canAssignToPublicClass(courseId, classId)` = 管理员 或 认领人 |
  | 能看这个班吗 | `canViewPublicClass(courseId, classId)` |
  | 留言等按班课授权 | `validateClassCourseAccess(classId, courseId)` |
  | 能放弃、清除认领吗 | `canReleasePublicClaim(claimTeacherId)` |

## 6. 新增一个权限点

改角色、权限点、菜单前**先问人**（根目录 `AGENTS.md` 第 6 条）。确认后按下面做：

1. **后端接口**：加 `@PreAuthorize("@ss.hasPermission('模块:资源:动作')")`。会产生数据的接口同时加 `@Idempotent`。Service 里补业务归属判断。
2. **新迁移**（如 `V22__...sql`，不能改已发布的迁移）：
   - 按父页面的权限标识找到父菜单，插入按钮；用 `NOT EXISTS` 保证可重复执行：

     ```sql
     INSERT INTO `system_menu`
     (`name`, `permission`, `type`, `sort`, `parent_id`, `path`, `icon`, `component`, `component_name`,
      `status`, `visible`, `keep_alive`, `always_show`, `creator`, `create_time`, `updater`, `update_time`, `deleted`)
     SELECT '按钮名', 'edu:xxx:yyy', 3, 10, page.`id`, '', '', '', NULL,
            0, b'1', b'1', b'1', 'system', CURRENT_TIMESTAMP, 'system', CURRENT_TIMESTAMP, b'0'
     FROM (SELECT MIN(`id`) AS `id` FROM `system_menu`
           WHERE `permission` = '父页面的权限标识' AND `type` = 2 AND `deleted` = b'0') page
     WHERE page.`id` IS NOT NULL
       AND NOT EXISTS (SELECT 1 FROM `system_menu` WHERE `permission` = 'edu:xxx:yyy' AND `deleted` = b'0');
     ```

   - 按**角色编码**（不是 ID）授权，同样只补缺失项。完整写法参考 `V18__v1_0_1_7_reliability_flow.sql` 里“按钮权限”一段。
   - 同步基线 `ry261-test.sql`，写 `deploy/database/tests/check-v22.py`。步骤见 [数据库迁移](../03-开发/数据库迁移.md)。
3. **接口权限快照**：

   ```bash
   cd NUS-backend
   TZ=Asia/Shanghai mvn -q -pl nus-server -am test -Dtest=EndpointPermissionsSnapshotTest \
     -Dsurefire.failIfNoSpecifiedTests=false -Dnus.permission.snapshot.update=true
   ```

   更新 `nus-server/src/test/resources/security/endpoint-permissions.tsv`。新增匿名或只需登录的接口，要在测试类里逐项写理由。
4. **权限矩阵**（需要 Docker，脚本只用本机一次性 MySQL 容器）：

   ```bash
   python3 deploy/database/tests/check-permissions.py --update --report /tmp/nus-permissions-report.md
   python3 deploy/database/tests/check-permissions.py --report /tmp/nus-permissions-report.md
   ```

   审查 `expected-role-endpoints.tsv` 的差异，尤其是从 0 变 1 的格子和学生可调用的非学生端接口。说明见 `deploy/database/tests/permissions/README.md`。
5. **前端**：按钮写 `auth: ['edu:xxx:yyy']`，与后端一致。
6. **发布**：升级脚本会清除菜单和权限缓存；在版本说明里提醒用户**重新登录**。学校自建的角色不会自动获得新权限点，要在版本说明里写明需要在“角色管理”里勾选。
