# ADR-004 公共课改为教师认领班级

- 状态：生效
- 相关版本：V1.0.1.5（公共课自动覆盖全部班级和教师）、V1.0.1.10（改为认领，迁移 V21）
- 日期：2026-10-12

## 背景

- V1.0.1.5 起，已审批的公共课自动关联当前学期所有正常班级（由 `EduPublicCourseSyncService` 建关联，`creator='system'`），**所有教师**都能查看公共课，并给任何已关联的班级布置任务。
- 结果是两位老师可能给同一个班重复上课，老师也会看到、干涉别人的班。
- 盘点还发现：公共课对任意教师放行的判断分散在多处，审批人的口径不一致，成绩趋势、课程分析和花名册导入导出有越权路径。

## 决定

- 公共课的班级由教师**认领**：同一班级、同一课程、同一学期只有一位认领人，写在 `edu_class_course.claim_teacher_id`、`claim_time` 上。“添加班级”在公共课里就是认领。
- 教师只看、只管自己认领的班级和自己布置的任务。
- 课程负责人只读查看全部；管理员、公共课审批人可以清除任一认领；课程团队成员在公共课里和普通教师一样。
- 任务按布置者授权：放弃认领后，布置者仍能查看、批改自己布置过的任务。
- 每学期分别认领。认领后补发该教师自己的“全课程任务”，系统同步建关联时不再补发任务。
- 判断逻辑集中在 `EduDataScopeService`。完整规则表见 [权限与数据范围](../权限与数据范围.md) 第 5 节。
- 升级时按历史任务回填认领人：本学期该班该课只有一位教师布置过（排除补发任务和布置者为 0 的任务）的，认领人就是他；其余留空。
- 专属课程不变。

## 理由

- 一个班一位老师，避免重复上课和互相干涉。
- 认领写在已有的班课行上，沿用同步建好的关联，不新增表。
- 把分散的放行判断收进一个服务，同时修掉越权路径。

## 后果

- 认领字段只能用条件 UPDATE 写，不能 `updateById`：同步靠 `updater='system'` 识别自动建的关联，`updateById` 会改掉它。认领、同步、补发共用课程锁。
- 自动封存空闲关联、学期收尾判断“自动建的关联”时，都要加上“未认领”条件，已认领的班课算在上课。
- 公共课的成绩册导入、花名册导入、留言回复收紧为布置者、认领人、班课助教和管理员。
- 留言接收人改为认领人和班课助教，未认领时发给课程负责人。
- 新学期开始时老师要重新认领，需要在使用说明里提醒。
