# ADR-002 封存与删除的统计口径

- 状态：生效
- 相关版本：V1.0.1.5（“删除”改“归档”）、V1.0.1.10（改称“封存”，计入分析；新增任务删除）
- 日期：2026-10-13

## 背景

- V1.0.1.5 把班级、课程、实训任务、班课的“删除”改成“归档”：数据保留、学生不可见、可恢复，但**不计入统计**。
- 学期收尾会把往期的班课、班级整批归档。结果是往期的合格率、成绩趋势、课程分析、排名都从分析页面消失了。
- 同时，老师确实需要把布置错的任务彻底去掉（V1.0.1.10 修复的“多班级建错班”就留下了一批错任务），而归档做不到“不计入任何统计”。

## 决定

两个动作，含义分开：

| | 封存（原“归档”） | 删除 |
| --- | --- | --- |
| 对象 | 班级、课程、班课、实训任务 | **只有实训任务** |
| 数据 | 保留，只读，可以恢复 | 逻辑删除，同一事务删除分配、提交、成绩、AI 初评、延期、提醒，不能恢复 |
| 看板总数、待办 | 不计 | 不计 |
| 分析类统计（合格率、趋势、课程分析、排名、AI 班级分析） | **计入** | 不计 |
| 学生端 | 待办里不出现，往期任务仍可只读查看 | 不再显示 |
| 谁能做 | 有相应权限的人 | 任务布置者本人和管理员；有提交时二次确认 |

- 界面上“归档”一律改称“封存”。接口路径和字段名不改。
- 完整口径表见 [数据模型](../数据模型.md) 第 3.3 节。

## 理由

- 封存针对的是往期学期，往期数据应当留在分析里，看板和待办只关心“现在在用的”。
- “删除”只用于真正移除，避免一个词两种含义。“归档”容易被理解成“收起来、不算了”，“封存”更接近“只读保留”。
- 只给任务加删除：班级、课程、班课牵涉面大，这次不做。

## 后果

- 升级到 V1.0.1.10 后，往期数据重新出现在分析里，老师看到的往期合格率等数字会变，已写入版本说明。
- 统计 SQL 分两套范围：看板用 `visibleHomeworkScope`（只算在用、状态 1、2），分析用 `analysisHomeworkScope`（含封存，状态 1、2、3）。新增统计时要先想清楚属于哪一类。
- 带 `delete` 字样的旧接口实际是封存（如 `/edu/homework/delete`、`EduClassServiceImpl.deleteClass`），真正删除任务是 `/edu/homework/remove`。
- 已经发出的通知不会因删除而撤回，点开会提示任务不存在。
- 前端文案扫描（`tests/copy/copyRules.ts`）拦截“归档”一词。
